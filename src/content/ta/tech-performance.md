> TA 岗的"一票否决项"：你说不清自己的场景多少帧、瓶颈在哪、怎么优化。
> 规则：**没有数据 = 没做过性能**。每个作品至少留 1 份性能记录。

---

## 1. 抓取流程（固定条件才有对比意义）

1. **固定机位**：用同一个相机/视角，记录相机位置与 FOV。
2. **固定分辨率**：1080p（`r.ScreenPercentage 100`）；测试时不要用窗口缩放。
3. **关后台**：浏览器、直播、录屏、Steam 等全部关掉；笔记本插电 + 高性能模式。
4. **等稳定**：进入场景后等 30 秒（着色器编译/纹理流送稳定）。
5. **记录命令**：`stat unit` → 截图；`stat gpu` → 截图；`stat rhi`/`stat streaming` → 截图。
6. **命名存档**：`P1_20270210_statunit_before.png` 放到 `05_Renders/性能/`。

> 如果是 MRQ 离线出图，记录"每帧耗时 / 总耗时 / 分辨率 / 采样数"，同样存表。

## 3. 判断瓶颈（`stat unit` 怎么读）

| 现象 | 结论 | 先优化什么 |
| --- | --- | --- |
| GPU ≈ Frame 且明显大于 Game/Draw | **GPU 瓶颈** | 分辨率、阴影、材质、Lumen、半透明 |
| Game 或 Draw 明显接近 Frame | **CPU 瓶颈** | DrawCall、蓝图/逻辑、剔除、LOD |
| Frame 远大于三者 | 同步/流送/编译卡顿 | 纹理流送、DDC、后台程序 |
| 显存接近 8GB | 显存压力 | 贴图、VSM、Lumen 硬件光追 |

**常用对照实验**（一次只改一个变量）：
- `r.ScreenPercentage 70`：帧时间明显下降 → GPU 像素瓶颈。
- 隐藏后处理（PostProcessVolume 关）：下降 → 后处理/半透明瓶颈。
- 关 VSM（临时）：下降明显 → 阴影瓶颈。
- 关 Lumen 反射：下降 → 反射瓶颈。

## 4. 优化实验记录（每个改动一行）

```markdown
| # | 改动 | 改动前 | 改动后 | 收益 | 画质影响 | 是否保留 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 贴图 4K → 2K | GPU 22.4ms / 显存 7.6GB | GPU 18.1ms / 显存 6.3GB | -4.3ms / -1.3GB | 特写略糊，可接受 | ✅ |
| 2 | 阴影 4096 → 2048 | ... | ... | ... | ... | ✅ |
| 3 | 半透明雾面积减半 | ... | ... | ... | ... | ❌ 画面变空 |
```

要求：
- 每次只改一个变量；
- 记录数值，不写"感觉快了"；
- 保留被否决的方案（面试会问"为什么不这样做"）。

## 5. 作品集"性能卡"（一页，排版用）

```markdown
### 性能（1920×1080 · RTX 4070 Laptop 8GB）
| 指标 | 数值 |
| --- | --- |
| GPU 帧时间 | 18.1 ms（≈55 fps） |
| 显存 | 6.3 GB / 8 GB |
| Draw Call | 1,240 |
| 可见三角面 | 8.6 M（Nanite） |
| 纹理流送 | 3.2 GB / 4.0 GB |
| 主要 GPU 开销 | Lumen 6.1ms ｜ 阴影 3.4ms ｜ 后处理 1.8ms |

**优化**：贴图 4K→2K（-1.3GB 显存）、阴影 4096→2048（-2.1ms）、半透明雾面积减半（-0.9ms）；
**取舍**：关掉硬件光追后反射精度下降，但换来稳定 55fps。
```

> 面试官看到这张卡，就知道你真的做过项目，而不是"渲染了一张图"。

## 7. 常见误区

1. **"我 60 帧"** —— 哪个机位？什么分辨率？什么设置？没有条件 = 没有数据。
2. **只测一次** —— 优化前后各测一次，条件必须一致。
3. **只看帧率不看显存** —— 8GB 显存爆了会疯狂掉帧/崩溃。
4. **优化了不记录** —— 面试问"你怎么优化的"，答不出具体数字。
5. **把编辑器视口当最终性能** —— 编辑器有额外开销，最终要在 Standalone/打包后复测。
