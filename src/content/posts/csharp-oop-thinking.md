这节课几乎没写代码,却是我目前回味最久的一节。TOM 老师开课先讲"编程思想"而不是语法,我一开始犯嘀咕:思想又不能编译,讲它干嘛?复习时才想明白:后面整章要讲的类、封装继承多态、接口,全靠"对象"这颗种子生根;心里没有对象,学再多关键字也只是背单词。

## 面向过程 vs 面向对象:一个关心"怎么做",一个关心"谁来做"

面向过程,就是把一件事拆成一串步骤,一步步执行。讲义里五子棋的例子:开始游戏→黑子走棋→绘制画面→判断输赢→白子走棋→循环。套路和我大一写 C 语言课程设计一样:主流程从上往下调用一个个函数,直白、跑得快,适合简单任务。

麻烦也在同一处:逻辑都搅在一口锅里,需求一变常要全局返工。面向对象换了个问法——先问"这件事里有谁",再让每个角色各管各的:落子输入归"玩家"对象,绘制棋局归"棋盘"对象,判断输赢归"规则"对象。TOM 说"加悔棋只改棋盘对象",我印象最深:职责划清,改动就只落在一小块,这是我写作业时最缺的意识。

## 类与对象,我这样理解

"玩家""棋盘"听着都是抽象概念,游戏里跑起来的"东西"从哪来?我想成图纸和实物:类是图纸,规定这个角色有什么、能做什么;对象是按图纸造出的实物,一张图纸能造出许多份,互不干扰。讲义的计算器例子,我照这思路写了一遍:

```csharp
// 我复习时写的:把讲义的计算器例子,换成"图纸"的思路
class Calculator
{
    // 加减乘除都"藏"在对象内部,外面只需调用方法
    public int Add(int a, int b) { return a + b; }
    public int Sub(int a, int b) { return a - b; }
    public int Mul(int a, int b) { return a * b; }
    public int Div(int a, int b) { return a / b; }
}

// 同一张"图纸",造出两台互不干扰的计算器
Calculator calc1 = new Calculator();
Calculator calc2 = new Calculator();
```

这段里 Calculator 是"图纸",calc1、calc2 是按它造的两台计算器,各算各的;加减乘除"藏"在对象内部,外面只管调用——"封装"我第一次有了体感。

## 为什么游戏开发需要面向对象

想通这些,游戏适合面向对象就顺理成章:英雄、怪物、技能本来就是有状态、有行为的"角色",自己管自己最合适。反过来,若用面向过程写怪物,得靠一堆散落的变量记状态、再写一堆函数去操作,怪一多必乱。而游戏需求变得快,加新怪多半只是再画一张"图纸",不用回头改别人;代价也写在讲义里:对象管理有开销、门槛高,适合大型项目。

## 小结与我的思考

这课复盘下来:面向过程擅长把简单的事快速做对,面向对象擅长把复杂的事拆清楚;关键不在立刻写类,而在先学会按对象划分职责。下一课要正式讲"类",我最好奇讲义预告的"继承":若"玩家"能派生出"战士""法师",共享公共行为又各有不同,是不是能省下大量重复代码?带着这个疑问,我盼着下一节课。
