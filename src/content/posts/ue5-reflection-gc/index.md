## 本集要解决的问题

开始写代码前，先理解 UE 的"地基"：C++ 是一门**没有内置反射**的语言，而 UE 需要在编辑器里"看见"并操作你的类（暴露属性给蓝图、自动管理内存）。它靠的是一套**自研反射系统 + 垃圾回收**，外加一个帮你生成代码的工具 **UHT**。

---

## 一、反射（Reflection）：程序在运行时检查自己

- **反射** = 程序在**运行时检查自身**的能力：程序分析自己内部的情况、收集关于自己的数据；
- 标准 C++ **没有内置反射**，所以 UE **自己设计了反射系统**来收集这些数据；
- 反射系统负责把数据与**虚幻编辑器系统**结合，把部分数据**暴露给蓝图**，并配合**垃圾回收**自动处理内存。

> 换句话说：你写的类只有被"反射系统登记"了，编辑器、蓝图、GC 才知道它的存在、才能操作它。

---

## 二、垃圾回收（GC）：自动删掉不再使用的对象

手动内存管理的痛点：在堆上 `new` 一个对象、指针变量指向它，一旦忘了 `delete`，就**内存泄漏**；而 C++ 不会替你释放，这是新手最容易踩的坑之一。

UE 的垃圾回收机制：

- 对象**参与 GC 系统**后，GC 会**跟踪引用该对象的变量数量**（引用计数）；
- 当对象**不再被任何变量引用**时，GC 自动删除它、释放内存；
- 于是你**不需要手动 `delete`**——这比裸 C++ 安全得多（参考：类似对类使用 `delete` 关键字，GC 帮你做了）。

> 注意区分：不是说"普通 C++ 对象会自动删除"，而是**参与 UE GC 系统的对象**（配合反射宏）才会被自动管理。

---

## 三、宏（Macro）：让反射系统认识你的代码

为了参与 UE 的反射/GC，类必须使用**特殊的 UE 宏**标记。先理解宏本身：

- **宏 = 一段被赋予名字的代码**；预处理器在**编译开始**时，把代码里出现宏名字的地方替换成那段代码。

接着是关键的角色 **UHT（Unreal Header Tool，虚幻头文件工具）**：

- 它在**项目编译时**扫描这些特殊宏；
- 每看到一个 UE 宏，就**自动为该类生成额外的代码**；
- 生成的代码让反射系统能从该类中获取信息。

### 常用的三个宏

| 宏 | 用在哪 | 作用 |
| --- | --- | --- |
| `UCLASS()` | 类声明顶部（继承自 `UObject` 的类） | 让类**参与反射系统**（也因此参与 GC） |
| `UPROPERTY()` | 变量声明前 | 让**变量**被反射系统识别（可暴露给蓝图） |
| `UFUNCTION()` | 函数声明前 | 让**函数**被反射系统识别（可暴露给蓝图） |

这就是"把变量和函数暴露给蓝图"的底层原理：**先用宏标记，UHT 据此生成代码，反射系统据此与编辑器协作**。

### 每个反射类头文件顶部的神秘 include

使用反射系统的类，头文件顶部都有一个特殊包含语句：

```cpp
#include "MyActor.generated.h" // 类名 + .generated.h
```

这个 `.generated.h` **不是手写的**——它包含 UHT **根据你写的宏模板代码自动生成**的反射代码。类体里通常还有一行：

```cpp
GENERATED_BODY() // UHT 自动生成的代码片段（一个"生成主体"宏）
```

- `GENERATED_BODY()` 代表**一段由 UHT 为这个类自动生成的代码**（之前在第 38 集创建 `AItem` 时已经见过它）；
- 有些宏带括号、可以像函数一样接受输入——这些输入叫**指定符（Specifier）**，能改变宏的行为；
- 你之后会通过给 `UPROPERTY` / `UFUNCTION` 加指定符，**自定义暴露给反射系统和蓝图的方式**（比如可编辑、只读、蓝图可调用……）。

---

## 小结与易错点

- **反射** = 运行时检查自身（C++ 没有，UE 自研补齐）；**GC** = 自动删除无引用对象，防内存泄漏；
- 想被反射系统管理（含 GC、暴露蓝图）：类用 `UCLASS()`、变量 `UPROPERTY()`、函数 `UFUNCTION()`；
- `#include "X.generated.h"` 与类内的 `GENERATED_BODY()` 都是 **UHT 自动生成代码的入口**，别手写、别删；
- 宏在编译期由预处理器展开；UHT 在编译时扫描宏并生成代码；
- 这些都是"骨架"，接下来的课程会反复用这些宏（写类、暴露变量给蓝图等），到时体会更深。
