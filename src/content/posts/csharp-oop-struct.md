上完 TOM 老师的结构体课,我把讲义又翻了两遍,把手边的例子在 Visual Studio 2022 里重新敲过、在 Unity 里跑过,才敢写这份笔记。课名只写了"结构体",真正让我卡壳的却是它和 class 的关系:同样是把好几个变量装进一个类型,C# 却给了两条路。下面是我的理解,不是复述讲义。

## 结构体,我这样理解

刚上课我很纳闷:不是早学了 class 吗,为什么还要 struct?老师用坐标、颜色一讲,我才转过弯:struct 是 C# 的值类型,专门封装一组关系紧密的小数据,比如一个三维坐标无非是三个 int,打包成一个整体来传递,省得把变量散得到处都是。它定位轻量,适合游戏中那种高频创建的位置坐标。

真正帮我的,是值类型和引用类型这条线。class 是引用类型,对象本体在堆上,变量里存的是地址;struct 是值类型,存在栈上,作为类里的字段时就跟着类待在堆里。我的比方:struct 像复印机吐出的纸,复制一份就是一份新的;class 像通讯录,转发名片给别人,大家看的还是同一份资料。

## 怎么定义和使用 struct

定义语法和类几乎一样:struct 关键字、名字、花括号,里面写字段和方法。我照着讲义里的 Point3D 写了一遍:

```csharp
// 用 struct 把三个整数打包成一个三维坐标点
public struct Point3D
{
    public int mX; // X 分量
    public int mY; // Y 分量
    public int mZ; // Z 分量

    // 结构体的字段必须在构造函数里全部赋值
    public Point3D(int x, int y, int z)
    {
        mX = x;
        mY = y;
        mZ = z;
    }
}
```

为了验证讲义里"实例化"的两种写法,我把它放进 MonoBehaviour 跑了一下:

```csharp
void Start()
{
    // 写法一:和类一样,用 new 创建
    Point3D p1 = new Point3D(1, 2, 3);

    // 写法二:只声明变量,不 new 也能直接给字段赋值
    Point3D p2;
    p2.mX = 4;
    p2.mY = 5;
    p2.mZ = 6;

    Debug.Log(p1.mX); // 输出 1
    Debug.Log(p2.mZ); // 输出 6,成员用点号访问
}
```

这两小段让我记住两件事:成员用点号访问;struct 可以 new,也可以不 new 直接声明出来用,而 class 少了 new 绝对不行。

## struct vs class

讲义里逐条讲的差别,我收进一张表:

| 对比 | struct(结构体) | class(类) |
| --- | --- | --- |
| 类型 | 值类型 | 引用类型 |
| 存储位置 | 栈上;作为类的字段时随类在堆上 | 对象本体在堆上 |
| 赋值行为 | 复制一份字段,互不影响 | 复制引用,共享同一个对象 |
| 继承 | 可继承多个接口;不能继承类和结构体 | 可继承接口和一个类;不能继承结构体 |
| 构造函数 | 不允许显式定义无参构造函数 | 允许显式定义无参构造函数 |
| 字段初始化 | 必须在构造函数里全部初始化 | 可以延迟初始化 |
| 实例化 | new 或不 new 都行 | 必须 new |
| 适用场景 | 数据导向:坐标、颜色、配置表 | 数据加功能:背包、公会、好友系统 |

表格之外的最后一课是赋值:Vector3 v2 = v1 后改 v2.mX,输出 v1.mX 仍是 1,因为复制的是全部字段;Player p2 = p1 后再改,输出跟着变,因为两个变量指向同一个对象。一正一反,比背定义管用。

## 容易踩的坑

下面几条是我自己踩过、或差点绕进去的。

1. 复制和共享记反。struct 赋值复制字段,改副本不影响原值;class 赋值复制引用,改一个两个都变。我一度以为改 v2 会连累 v1,又以为 p2 = p1 是各改各的,方向记反了两次。
2. 把类的习惯带进 struct。给字段写默认值(如 mTimer = 16800)编译报错;显式写无参构造函数也不行;字段必须在构造函数里初始化完,漏一个也报错。class 则没这些限制。
3. 不看场合乱用。坐标、颜色、配置表这类纯数据适合 struct;背包、公会、好友这类数据带功能的系统该用 class。硬把业务系统塞进 struct,或把小数据都做成 class,都是没想清楚它是值还是对象。
4. 混淆实例化方式。我总习惯默认 struct 也必须 new,写 class 时又差点省掉。规则就一句:引用类型要先 new 出对象,值类型天生自带数据,new 不 new 都行。

## 小结与我的思考

最大的收获,是把值类型和引用类型从概念落到代码行为:赋值是复制还是共享、数据存栈还是堆、能不能不 new、能不能延迟初始化,全由这一条主线决定。复习时我把讲义里那张栈与堆的内存图重画了一遍,再对照 v1、v2 和 p1、p2 两组代码,一切就对上了。

往后遇到该选哪个,我先问自己:数据量小不小?会不会被高频创建?它是纯数据还是带一堆功能逻辑?前两个偏小、第三个是纯数据就用 struct,否则用 class。最后我打算把讲义结尾敲黑板的 Rectangle 作业(算矩形面积)完整跑通——动手做一遍,比看十遍笔记记得牢。
