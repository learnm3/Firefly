这节 C#/Unity 入门课讲运算符。开课前我以为无非是背符号,听完才明白它其实在讲"怎么指挥数据干活"。讲义上的表格我记不牢,于是在 Unity 2023.2 + Visual Studio 2022 的环境里把例子一个个敲出来,用 Debug.Log 亲眼看到结果,才算真正消化。这篇笔记是我复习后的理解,不是把讲义复述一遍。

## 运算符,我这样理解

讲义把运算符定义成"告诉编译器执行特定操作的符号",有点绕。我的说法是:运算符就是对数据做的"动作"。数据要么躺在变量里,要么正在流动,运算符负责让它们动起来。按用途可以分为几大类:

- 算术运算符(+ - * / % ++ --):管"算",把数值算成新数值;
- 比较运算符(`== != > < >= <=`):管"问",比如"血量还大于 0 吗",答案只能是 true 或 false,也就是返回 bool;
- 逻辑运算符(&& || !):管"拼判断",把几个 bool 组合成一个新的 bool;
- 赋值运算符(= += -= 等):管"存",把右边算好的结果写进左边变量;
- 讲义还列了位运算、三目运算符等,我暂时把它们当作"别的工具箱",用到再回来翻。

这节课我最在意的点是每类运算符"返回什么类型":算术返回数值,比较和逻辑返回 bool。写判断前先想清楚这一点,思路就不会乱。

## 算术与自增自减

这组最像小学算术,但有两个新手容易忽略的脾气:一是两个 int 相除会"截断"小数,二是 % 不是百分号而是取余,能整除时余数为 0。加餐是 ++ / --:能让整数自己加 1 或减 1,可它放在变量前还是后,结果竟然不一样。讲义用 x = 5 一步步演示,我照敲了一遍,又补了两行自测:

```csharp
int a = 10;
int b = 20;

// 四则运算,结果仍是 int
Debug.Log(a + b);   // 30
Debug.Log(b - a);   // 10
Debug.Log(a * b);   // 200
Debug.Log(b / a);   // 2

// 我补的自测:验证"截断小数"和"取余"
Debug.Log(7 / 2);   // 3,小数部分被截掉
Debug.Log(10 % 3);  // 1,10 = 3 * 3 + 1
Debug.Log(b % a);   // 0,能整除,余数为 0

// 讲义里的经典:x++ 与 ++x
int x = 5;
int y = x++;        // 先用后加:y 先拿到 5,x 再变成 6
int z = ++x;        // 先加后用:x 先变成 7,z 拿到 7
Debug.Log(x);       // 7
Debug.Log(y);       // 5
Debug.Log(z);       // 7
```

看完这组输出我彻底记住了:x++ 是"先把当前值给别人,自己再加 1",++x 反过来"自己先加 1,再把新值给别人"。位置差一点,结果就完全不同。

## 比较、逻辑与复合赋值

比较运算符像给程序装了一双"眼睛",而且它和算术最大的区别是:返回值永远是 bool,不是数值。逻辑运算符负责把几双眼睛的结论"拼"起来——&& 要两边都为 true 才为 true,|| 有一边为 true 就为 true,! 则把结果取反。我还发现 && 有个"短路"脾气:左边已经是 false 时,右边根本不会被执行,所以可以把判断开销小的条件放左边。复合赋值就纯粹是缩写:讲义里写 C += A 等价于 C = C + A,少敲一遍变量名。我把它们凑在一个"角色血量"的小例子里:

```csharp
int hp = 80;
int maxHp = 100;
bool hasShield = true;

// 比较运算符:返回 bool
bool alive = hp > 0;           // true,还活着
bool full = hp == maxHp;       // false,没满血
bool damaged = hp != maxHp;    // true,掉过血
bool healthy = hp >= 60;       // true,状态不错

// 逻辑运算符:把判断组合起来
bool lowHp = hp <= 30;             // false
bool danger = lowHp && !hasShield; // 低血且没护盾才算危险
bool callHelp = lowHp || hp < 50;  // 低血或血量不足 50 就叫支援
Debug.Log(danger);    // false;lowHp 已是 false,&& 直接短路
Debug.Log(callHelp);  // false

// 复合赋值:相当于 hp = hp - 25
hp -= 25;             // 被打了一下
Debug.Log(hp);        // 55
hp += 15;             // 吃到补给
Debug.Log(hp);        // 70
```

## 优先级与可读性

当一行里挤着多个运算符时,C# 不是从左往右傻算,而是按优先级从高到低执行。我记住的主干顺序是:算术运算先于比较,比较先于逻辑,逻辑里 && 又比 || 靠前,赋值基本排在最后。不过讲义自己也说了,这些不必死记硬背。让我最有体会的是随堂作业的闰年判断 `(year % 4 == 0 && year % 100 != 0) || year % 400 == 0`:式子不长,% 、==、&&、|| 却全挤在一起,不查表很难一眼说清谁先执行。所以我现在的做法是:拿不准就直接加括号,把想表达的顺序写出来。括号多一点并不丢人,反而让读代码的人(包括一周后的自己)一眼就懂,这比硬背优先级表可靠得多。

## 容易踩的坑

我把讲义提醒过、以及自己真犯过的错记在这里:

1. **判断相等误写成 =**。比较要用 ==,一个 = 是赋值。本意是"判断是否等于 60",写成 `if (score = 60)` 就成了"把 60 塞进 score",判断没了,还容易直接编译报错,而且这类错误往往不容易一眼看出来。
2. **整数除法丢小数**。两个 int 相除,结果只保留整数部分,7 / 2 得到 3。讲义专门标注了"整数除法会截断小数",我当时没在意,直到自己算比例才发现。
3. **i++ 和 ++i 分不清**。同样从 x = 5 开始,y = x++ 得到 5,x 变 6;若随手写成 y = ++x,就变成 y 和 x 都是 6,后面所有依赖 x 的值全对不上。
4. **% 的余数方向想当然**。10 % 20 的结果是 10——被除数比除数小时,余数就是被除数本身;只有真能整除(如 20 % 10)才是 0。判断"能否整除"时很容易在这里翻车。
5. **除以 0**。我试过把除数写成 0,Unity 控制台立刻报错。以后凡是用变量做除数,我都会先确认它不为 0。

## 小结与我的思考

回看这一节,内容不难但特别"碎":符号多、分类多、优先级还要记。我的学习办法是把它们当"动词"而不是"符号"——算术是算,比较是问,逻辑是拼,赋值是存;先搞清楚每个动作返回什么类型,再配合 Debug.Log 反复验证,自然就记住了。讲义最后说这部分要"多练习",我很认同:表格看十遍,不如亲手敲一遍。下一步我打算多写几个类似"血量判断"的小例子,把 &&、||、! 用顺手——毕竟游戏里到处都是这类判断,不过那就要等后面的课程继续给我"弹药"了。
