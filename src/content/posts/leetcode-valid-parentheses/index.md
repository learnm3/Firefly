## 题目回顾

[LeetCode 20. Valid Parentheses](https://leetcode.cn/problems/valid-parentheses/) — 难度：简单

**给定一个只包括 `'('`、`')'`、`'{'`、`'}'`、`'['`、`']'` 的字符串 `s`，判断字符串是否有效。**

有效字符串需满足：
1. 左括号必须用相同类型的右括号闭合
2. 左括号必须以正确的顺序闭合

```
输入：s = "()[]{}"   →   true
输入：s = "(]"       →   false
输入：s = "([)]"     →   false（交叉闭合非法）
输入：s = "{[]}"     →   true（嵌套合法）
```

## 游戏场景：这道题在游戏里到底干什么用？

### 场景一：技能组合的括号配对（动作游戏 / MOBA）

> 很多动作游戏的技能表用括号表示"组合技"或"子技能"：`Q(E(R))` 表示 Q 技能中嵌套 E 技能、E 里再嵌套 R 技能。战斗系统需要校验玩家的输入**是否构成合法的组合链**——就像校验括号是否配对。

```
玩家输入：Q E R ) )    →   Q(E(R)) 缺一个右括号 → 非法，技能不触发
玩家输入：Q E ) R )    →   Q(E)R) 交叉 → 非法（E 没闭合就开 R）
玩家输入：Q E ) )      →   Q(E) 合法 → 触发组合技
```

**这就是「有效的括号」的直白映射**：左括号 = 组合技开始，右括号 = 组合技结束，嵌套 = 子技能。战斗系统用栈来判定"当前这个右括号配对的是哪个左括号"——最近开的组合必须先关。

### 场景二：配置文件 / 指令脚本的合法性检查（工具链）

> 游戏的配置文件（比如技能数值表、关卡脚本）经常用 `{}`、`[]`、`()` 表达嵌套结构。加载配置前先做一次括号校验，能避免解析到一半崩溃。

```
技能配置：
  Skill_Combo {
    Damage: 100
    Effects: [ { Type: "Knockback", Power: 2 } ]
  }
加载前检查所有括号是否配对、顺序是否正确 → 不合法直接报错提示策划
```

### 场景三：聊天 / 输入指令的括号补全（MMO 社区）

> 玩家输入 `/trade [item] (price)` 这类指令时，客户端可以先做括号校验，非法输入给出提示而不是发到服务器。

## 解法分析

### 解法一：栈（标准答案）— O(n)

**核心思想**：栈是"最近配对"问题的天然数据结构。遇到左括号入栈，遇到右括号弹出栈顶检查是否配对——**栈顶永远是最近未闭合的左括号**。

```cpp
bool isValid(string s) {
    stack<char> st;
    // 右括号 → 匹配的左括号的映射
    unordered_map<char, char> pairs = {
        {')', '('}, {']', '['}, {'}', '{'}
    };

    for (char c : s) {
        if (pairs.count(c)) {
            // 是右括号：栈顶必须是配对的左括号
            if (st.empty() || st.top() != pairs[c]) {
                return false;   // 无配对 或 交叉闭合
            }
            st.pop();
        } else {
            // 是左括号：入栈
            st.push(c);
        }
    }
    // 全部处理完，栈必须为空（所有左括号都被闭合）
    return st.empty();
}
```

**为什么正确**：
- **嵌套**：`{[]}` — 遇到 `[` 入栈，遇到 `]` 弹出 `[` 配对，遇到 `}` 弹出 `{` 配对 → 由内向外逐层闭合 ✅
- **交叉**：`([)]` — 遇到 `]` 时栈顶是 `(` 而非 `[` → 返回 false ✅
- **多余右括号**：`()` 后栈空时再遇到 `)` → st.empty() 返回 false ✅
- **多余左括号**：`(()` 结束时栈不为空 → false ✅

> **面试必答要点**：
> 1. 为什么用栈？—— 右括号永远和**最近**未闭合的左括号配对，栈顶天然是"最近"，O(1) 取栈顶
> 2. 为什么不用计数器？—— `([)]` 用计数器分不出交叉（每类括号计数都非负），栈能精确匹配顺序
> 3. 提前终止优化：`s.length()` 为奇数直接 false；遍历中栈空却遇到右括号直接 false

### 解法二：替换法（理解用，不推荐面试）— O(n²)

不断把 `()`、`[]`、`{}` 替换为空串，最后看是否为空：

```cpp
bool isValid(string s) {
    while (s.find("()") != string::npos || s.find("[]") != string::npos || s.find("{}") != string::npos) {
        s = regex_replace(s, regex("\\[\\]|\\(\\)|\\{\\}"), "");
    }
    return s.empty();
}
```

能过但 O(n²) 且代码啰嗦——**面试用这个会被追问"为什么不用栈"**，不建议作为主答案。

## 与游戏开发的更深联系

### 为什么栈在游戏引擎里无处不在

| 游戏系统 | 栈的体现 |
|---|---|
| **UI 导航栈** | 打开面板入栈、关闭出栈——返回键回到上一页（和括号配对一模一样） |
| **状态机调用** | 技能释放时的状态入栈/出栈，恢复之前的状态 |
| **撤销系统（Undo）** | 操作记录栈，Ctrl+Z 出栈回退 |
| **表达式求值** | 游戏内脚本引擎解析 `(a+b)*c` 时的运算符栈 |
| **背包/任务弹窗** | 层层打开的界面关闭顺序 |

**最贴切的类比**：**UI 界面栈**——打开技能面板（入栈 `(`），再打开属性面板（入栈 `[`），关闭时先关属性再关技能（`]` 然后 `)`）——**必须后进先出**，否则 UI 状态错乱。面试官听到这个例子会点头。

### 面试怎么答"栈在游戏里用过吗"

**推荐回答**（结合本项目）：

> 「我在 UE 里做 UI 时接触过类似思想——**界面导航栈**：打开面板就入栈，关闭就出栈，保证返回键总是回到上一页（后进先出）。这和括号配对的逻辑完全一致：最近打开的面板必须最先关闭。还有**技能系统的输入缓冲**：连招指令按顺序处理，嵌套组合技的开启/闭合也用栈维护。」

3. 能举出游戏里的栈例子（UI 导航栈最经典）
