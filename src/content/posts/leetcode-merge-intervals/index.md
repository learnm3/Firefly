## 题目回顾

[LeetCode 56. Merge Intervals](https://leetcode.cn/problems/merge-intervals/) — 难度：中等

**以数组 `intervals` 表示若干个区间的集合，其中单个区间为 `intervals[i] = [starti, endi]`。请你合并所有重叠的区间，并返回一个不重叠的区间数组。**

```
输入：intervals = [[1,3],[2,6],[8,10],[15,18]]
输出：[[1,6],[8,10],[15,18]]
解释：区间 [1,3] 和 [2,6] 重叠，合并成 [1,6]
```

**直观理解**：把重叠的时间段合并成更大的时间段。

## 游戏场景：这道题在游戏里到底干什么用？

### 场景一：Buff 生效时间段合并（MMO / RPG）

> 角色身上挂着各种 Buff，每个 Buff 有生效时间段。比如"攻击+10%"持续 [1,3] 秒、"攻速+20%"持续 [2,6] 秒——**重叠的时间段里，角色的加成状态需要合并计算**。

```
Buff 时间段：
  攻+10%:  [1,3]
  速+20%:  [2,6]     ← 与 [1,3] 重叠
  防+5%:   [8,10]
  闪避:    [15,18]

合并后（按覆盖范围）：
  [1,6]（这 5 秒内至少有一个 Buff）
  [8,10]
  [15,18]
```

**这就是「合并区间」的直译**。战斗系统计算"当前时刻有哪些 Buff 生效"时，先把所有 Buff 时间段合并成互不重叠的块，再逐块计算加成。

> **面试延伸**：真实 Buff 系统更复杂——不同 Buff 加成**可叠加**（要记录每段有几个 Buff）而不是简单合并。这时需要"区间扫描 + 计数"（差分数组），是这道题的进阶变体。能说出这个区别，面试官会认可你的理解深度。

### 场景二：掉落概率区间归并（抽卡 / 战利品）

> 抽卡系统里，每个物品的掉落概率可以表示为 [0,0.6)、[0.3,0.9) 这样的区间。合并重叠区间 = 算"某一档位至少掉什么"的总概率区间。

### 场景三：任务时间段合并（日程/活动系统）

> 游戏活动的时间段（周末活动、限时副本）可能有重叠，合并后得到"总有活动可玩"的时间块，用于安排服务器维护窗口。

### 场景四：在线玩家统计（运营系统）

> 服务器记录玩家上线时间段，合并重叠区间得到"同时在线人数峰值"的分析基础（配合差分数组）。

## 解法分析

### 解法：排序 + 扫描 — O(n log n) ⭐ 标准答案

**核心思想**：**先按左端点排序**，然后逐个扫描——如果新区间与当前合并区间重叠（`新左 <= 当前右`），扩展右端点；否则开启新区间。

```cpp
vector<vector<int>> merge(vector<vector<int>>& intervals) {
    if (intervals.empty()) return {};
    // 按左端点排序
    sort(intervals.begin(), intervals.end());

    vector<vector<int>> result;
    result.push_back(intervals[0]);   // 先放入第一个区间

    for (int i = 1; i < intervals.size(); i++) {
        auto& cur = result.back();
        // 重叠判定：新区间左端点 <= 当前合并区间的右端点
        if (intervals[i][0] <= cur[1]) {
            cur[1] = max(cur[1], intervals[i][1]);   // 扩展右端点
        } else {
            result.push_back(intervals[i]);          // 不重叠，开新区间
        }
    }
    return result;
}
```

**为什么正确**：
- **排序后**，后面的区间左端点必然 >= 前面的，所以只需比较"新区间左 vs 当前合并区间右"
- 重叠时扩展右端点取 max（新区间可能更长）
- 不重叠时开启新块，且后续区间只与新块比较（因为已排序，不会与旧块重叠）

> **面试必答要点**：
> 1. **为什么先排序？** —— 排序后只需单向比较，把"判断两个区间是否重叠"简化成"新左 <= 当前右"，O(n log n) 排序 + O(n) 扫描
> 2. **重叠条件**：`新区间左端点 <= 当前合并区间右端点`（注意 `<=`，边界相接也算重叠）
> 3. **这是区间类问题的万能模板**：排序 → 扫描 → 按条件合并/分裂

### 变体：区间扫描（差分数组）— 统计重叠数

## 与游戏开发的更深联系

### 区间思维在游戏中的位置

| 游戏系统 | 区间的体现 |
|---|---|
| **Buff/Debuff 管理** | 生效时间段合并、刷新时长 |
| **技能冷却** | 冷却区间与持续区间 |
| **碰撞检测** | AABB 在轴上的投影区间重叠判定 |
| **活动排期** | 活动时间窗口合并 |
| **掉落/概率** | 概率区间归并 |

**更深一层**：碰撞检测里 **AABB（轴对齐包围盒）** 的重叠判断，本质就是"两个区间是否重叠"的三维扩展——`box1.maxX > box2.minX && box1.minX < box2.maxX` 就是区间重叠判定的翻版。UE 的碰撞系统底层大量用区间思想。

### 面试怎么答"区间/排序在游戏里用过吗"

**推荐回答**（结合本项目）：

> 「我做 UE 项目时接触过区间思想——比如 **Buff 系统**：多个 Buff 的生效时间段需要合并计算当前加成，就是先排序再合并区间。还有 **碰撞检测**：AABB 重叠判断本质上就是区间重叠的判定（maxX > minX && minX < maxX）。我理解排序的作用是把无序区间变成可单向扫描的结构，这个思想在资源加载顺序、事件调度里也常用。」
