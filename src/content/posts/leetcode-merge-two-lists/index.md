## 题目回顾

[LeetCode 21. Merge Two Sorted Lists](https://leetcode.cn/problems/merge-two-sorted-lists/) — 难度：简单

**将两个升序链表合并为一个新的升序链表并返回。新链表是通过拼接给定的两个链表的所有节点组成的。**

```
输入：l1 = [1,2,4], l2 = [1,3,4]
输出：[1,1,2,3,4,4]
```

**直观理解**：两列已经排好队的物品，合成一列仍然有序的。

## 游戏场景：这道题在游戏里到底干什么用？

### 场景一：副本掉落物按品质合并（MMO）

> 你打了两个副本，掉落物各自按品质排序（白色→绿色→蓝色→紫色→金色）。背包系统要把两份掉落**合成一份仍然有序**的列表，方便玩家一眼看到最好的是什么。

```
副本A掉落（按品质）：[白, 绿, 蓝]
副本B掉落（按品质）：[白, 蓝, 金]
合并后：[白, 白, 绿, 蓝, 蓝, 金]  ← 仍然有序
```

这正是「合并两个有序链表」：两个链表都是有序的，归并后依然有序。

> **面试延伸**：如果掉落了 **K 个副本**（K 个有序链表），就是 [合并 K 个升序链表（23）](https://leetcode.cn/problems/merge-k-sorted-lists/)——用优先队列逐个取最小，或两两归并。能主动提到变体，面试官会加分。

### 场景二：合成配方的有序归并（生存建造）

> 生存游戏里，背包物品按类型+等级排序，合成台要把两堆材料（各自有序）归并成一份完整清单，检查哪些配方凑齐了。

### 场景三：排行榜分页合并（竞技游戏）

> 两个服务器段的排行榜（各按分数降序），跨服合并时归并成一份总榜。虽然实际用数组更多，但**归并思想**完全相同——双指针逐个取小的。

### 场景四：存档差异合并（工具链）

> 两个存档文件的事件列表各自按时间排序，合并成完整时间线——归并思想在版本管理、日志合并里到处都是。

## 解法分析

### 解法一：迭代 + dummy 节点（标准答案）— O(n+m)

**核心思想**：`dummy` 哨兵节点避免处理"链表为空"的边界，双指针逐个取较小节点接在结果尾部。

```cpp
struct ListNode {
    int val;
    ListNode* next;
    ListNode(int x) : val(x), next(nullptr) {}
};

ListNode* mergeTwoLists(ListNode* l1, ListNode* l2) {
    ListNode dummy(0);        // 哨兵节点：结果链表的虚拟头
    ListNode* tail = &dummy;  // 指向结果链表的尾部

    while (l1 && l2) {
        if (l1->val <= l2->val) {
            tail->next = l1;
            l1 = l1->next;
        } else {
            tail->next = l2;
            l2 = l2->next;
        }
        tail = tail->next;
    }

    // 其中一条走完，直接把剩下整条接上
    tail->next = l1 ? l1 : l2;

    return dummy.next;   // 跳过哨兵，返回真正的头
}
```

**为什么需要 dummy 节点（面试必答）**：
- 没有 dummy 时，**第一个节点**要特殊处理（要么判空，要么单独判断谁开头）
- dummy 让"当前尾部"永远存在，`tail->next = ...` 无需分支——代码简洁且不易错
- 这是链表题**通用技巧**：删除节点、反转、合并都适用

**复杂度**：时间 O(n+m)，空间 O(1)（只移动指针，没新建节点）。

### 解法二：递归 — O(n+m)

```cpp
ListNode* mergeTwoLists(ListNode* l1, ListNode* l2) {
    if (!l1) return l2;
    if (!l2) return l1;
    if (l1->val <= l2->val) {
        l1->next = mergeTwoLists(l1->next, l2);
        return l1;
    } else {
        l2->next = mergeTwoLists(l1, l2->next);
        return l2;
    }
}
```

**思想**：每次取较小的节点作为头，剩下的继续归并（递归子问题）。**递归空间 O(n+m)**（调用栈），迭代更省空间。

> **面试建议**：两种都写出来——先迭代（主答案），再补一句"递归写法是取较小的做头、递归合并剩余"，展示你掌握两种实现。

## 与游戏开发的更深联系

### 归并思想在游戏中的位置

| 游戏系统 | 归并的体现 |
|---|---|
| **掉落合并** | 多来源掉落物按序合成（本题直译） |
| **排行榜合并** | 跨服榜、赛季榜数据归并 |
| **日志系统** | 多线程日志按时间戳归并成完整时间线 |
| **帧事件合并** | 多系统事件流合并排序 |
| **存档合并** | 本地存档 + 云端存档按时间线归并 |

**更深一层**：合并两个有序链表是**归并排序**的核心子过程（Merge 步骤）。游戏里任何"排序 + 合并"场景都隐含归并思想——比如 UE 的场景加载顺序合并、资源依赖拓扑排序后的合并。

### 面试怎么答"链表/归并在游戏里用过吗"

**推荐回答**（结合本项目）：

> 「我在做 UE 项目时接触过类似思想——**掉落系统**里多份奖励列表需要按品质合并展示，就是归并的思路。还有**加载顺序**：多个模块的资源加载列表按优先级合并，用归并保持有序。链表的 **dummy 节点技巧**也很实用：处理链表头边界时避免大量 if 分支，我在写数据驱动组件时也用了类似技巧（虚拟头节点）。」

## 总结：这道题你该带走什么

1. **dummy 节点**技巧能独立写出（边界处理的关键）
2. 迭代 + 递归两种写法都掌握
3. 能举出游戏场景（掉落合并最直观）
4. 知道它是**归并排序的核心子过程**，能引出 K 路归并变体
5. 空间 O(1)（迭代）vs O(n)（递归）的差异说清楚
