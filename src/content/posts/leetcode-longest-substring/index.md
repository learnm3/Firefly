## 题目回顾

[LeetCode 3. Longest Substring Without Repeating Characters](https://leetcode.cn/problems/longest-substring-without-repeating-characters/) — 难度：中等

**给定一个字符串 `s`，请你找出其中不含有重复字符的最长子串的长度。**

```
输入：s = "abcabcbb"
输出：3
解释：最长子串是 "abc"，长度为 3（"bca" 也是）
```

**直观理解**：找一段**内部没有重复字符**的最长连续片段。

---

## 游戏场景：这道题在游戏里到底干什么用？

### 场景一：技能冷却条——最大无冲突连招窗口（MOBA / 动作游戏）

> 你有一排技能，每个技能用字母标记（a、b、c...）。同一技能短时间内不能连续使用两次（CD 中）。问：**最多能连续释放多少个互不相同的技能？**

```
技能序列：a b c a b c b b
                 ↓
最多无重复段：a b c（长度 3）——因为第 4 个技能 a 还在 CD
```

这正是「无重复字符的最长子串」：`s` 是技能序列，重复字符 = CD 中的技能。动作游戏（战双/鸣潮的连招设计）里，**"在一段时间内不重复使用技能"的约束**是最常见的战斗节奏设计——找出理论最长连招就是这道题。

> **面试延伸**：真实连招系统更复杂——技能 CD 长度不同（`"aa"` 中间隔 2 秒才能再用）。那就要升级为**带权滑动窗口**（窗口内相同字符需要间隔 >= k），是这道题的变体，能说出来的话加分。

### 场景二：背包整理——最大无重复物品段（原神 / 暗黑）

> 背包里物品按获取顺序排列，同一种物品要合并。整理时你希望找到**最长的"每种物品只出现一次"的连续段**，一次性把它们拖到仓库。

```
物品序列：剑 盾 药 剑 盾 盾 药
             ↓
最长互异段：剑 盾 药（3 件）——再往后拿剑就和第 1 件重复了
```

### 场景三：任务系统——无冲突的每日任务链（MMO 日常）

> 每天的任务列表按刷新顺序排列，**同一个 NPC 的任务每天只能接一次**。问最多能连续接多少个不同 NPC 的任务。

### 场景四：Buff 时间轴——互斥 Buff 的最长生效窗口

> 角色身上挂着各种 Buff（攻、防、速...），同类 Buff 不能叠加（取最高值）。在 Buff 时间轴上找**最长的"无同类 Buff"时段**——这直接决定战斗中的属性峰值窗口。

### 场景五：输入处理——按键去抖 / 指令缓冲（格斗游戏）

> 格斗游戏的指令缓冲里，同一招式指令短时间内重复输入会被吞掉。找**最大的无重复指令窗口**，就是你能"干净地"连续输入多少个不同指令——这关乎搓招成功率。

## 解法分析

### 解法一：暴力枚举 — O(n²)

枚举所有子串，逐个检查是否有重复字符。

```cpp
bool hasAllUnique(const string& s, int l, int r) {
    unordered_set<char> seen;
    for (int i = l; i <= r; i++) {
        if (seen.count(s[i])) return false;
        seen.insert(s[i]);
    }
    return true;
}

int lengthOfLongestSubstring(string s) {
    int n = s.size(), ans = 0;
    for (int i = 0; i < n; i++) {
        for (int j = i; j < n; j++) {
            if (hasAllUnique(s, i, j)) {
                ans = max(ans, j - i + 1);
            }
        }
    }
    return ans;
}
```

**复杂度**：O(n³)（枚举 O(n²) × 检查 O(n)）——太慢，面试必被要求优化。

**游戏视角**：这就是"遍历所有可能的技能连招组合再逐个验证"——排列组合爆炸，真实引擎里不可能这么干。

### 解法二：滑动窗口 — O(n) ⭐ 标准答案

**核心思想**：维护一个"窗口"（左指针 l ~ 右指针 r），窗口内保证无重复字符。

- 右指针 r 不断向右扩展（"尝试把下一个技能加进连招"）
- 一旦新字符与窗口内重复（"技能还在 CD"），**左指针 l 收缩**，把重复的那个字符挤出窗口
- 每一步记录窗口最大长度

```cpp
int lengthOfLongestSubstring(string s) {
    unordered_map<char, int> lastPos;   // 字符 → 它上一次出现的位置
    int ans = 0, l = 0;                 // l 是窗口左边界
    for (int r = 0; r < s.size(); r++) {
        char c = s[r];
        if (lastPos.count(c) && lastPos[c] >= l) {
            // c 在窗口内出现过 → 把左边界推进到它上一次出现位置的后一个
            l = lastPos[c] + 1;
        }
        lastPos[c] = r;                 // 更新 c 的最新位置
        ans = max(ans, r - l + 1);      // 记录当前窗口长度
    }
    return ans;
}
```

**为什么是 O(n)**：左指针 l 和右指针 r 各最多移动 n 次，总操作 O(n)。`lastPos` 哈希表 O(1) 查询。

**游戏视角**：这就是真实引擎里的做法——**不回头**。右指针像"尝试加技能"，左指针像"CD 到了就移除最前面那个"：整个处理像一条不断滑动的传送带，每个字符最多进出各一次。

> **面试必答要点**：
> 1. 为什么 l 要取 `max(l, lastPos[c]+1)`？—— 因为字符可能在窗口**之前**出现过，不算重复，不能把 l 拉回去
> 2. 为什么用哈希表记位置而不是用 Set？—— 需要知道"上一次出现的位置"来精确收缩，Set 只知道"有没有"
> 3. 空间 O(字符集大小)（ASCII 可用 `int[128]` 数组替代哈希表，更快）

## 与游戏开发的更深联系

### 为什么滑动窗口是游戏编程的"底层思维"？

滑动窗口的本质是**"维护一个满足条件的最优区间，双指针只前进不后退"**。这个思维在游戏客户端到处可见：

| 游戏系统 | 窗口的体现 |
|---|---|
| **技能冷却管理** | 冷却时间数组的滚动窗口，判断技能是否可用 |
| **伤害判定（Overlap）** | 一帧内的命中对象列表，滑动去重避免重复判定 |
| **输入缓冲（Input Buffer）** | 最近 N 帧的输入窗口，格斗游戏搓招判定 |
| **帧率平滑（Frame Smoothing）** | 最近若干帧的耗时窗口，计算平均帧时间 |
| **内存池回收** | 对象生命周期的滚动窗口，何时安全复用 |
| **网络包重排序** | 接收缓冲的滑动窗口，处理乱序到达的包 |

### 面试怎么答"滑动窗口在游戏里用过吗"

**推荐回答**（结合本项目）：

> 「我在做 UE5 角色控制时接触过类似思想——比如**输入缓冲**：只保留最近几帧的输入指令（滑动窗口），既保证搓招响应，又避免旧指令干扰新操作。还有**帧率统计**：用最近 60 帧的耗时窗口算平均帧时间，而不是全部历史，避免内存无限增长。滑动窗口的本质是『只保留相关的一段，用双指针维持区间』，这个思维在性能敏感的客户端编程里非常常用。」
