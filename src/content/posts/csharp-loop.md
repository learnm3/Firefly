这周的课讲 C# 的循环语句,环境还是那套 Unity2023.2.20f1c1 + Visual Studio 2022。老实说,我上学期在 C 语言课里就和 for、while 打过照面,起初觉得"这有什么好学的",可这次站在游戏开发的角度重过一遍,课后又自己敲代码验证,才咂摸出一点不一样的味道。下面是我上完课、复习完讲义之后的理解,尽量用我自己的话讲出来。

## 循环,我这样理解

讲义开头那句话我记住了:循环就是重复执行一段代码,直到满足终止条件。翻译成大白话——重复的体力活都可以甩给程序。想打印一堆整数,人肉复制粘贴几十行 Debug.Log 显然不现实,循环几行就能搞定。

四种循环的"节奏",我是这样记的:

- **for**:数着来。已经知道大概要跑几次,初始化、条件、变化三件事都写在同一个括号里;
- **while**:看着办。只要条件成立就一直跑,条件一开始就不成立的话,一次都不执行;
- **do...while**:先干再说。不管条件怎样,先执行一次,再回头判断;
- **foreach**:挨个过。完全不碰下标,把数组、列表里的元素逐个取出来,讲义里那个 int 数组的例子我跑过,0、1、1、2、3、5 被依次打印出来,很直观。

所以我的选型直觉很简单:要精确控制"第几次"用 for,次数得看运行时条件用 while,必须至少执行一次就用 do...while,只是单纯遍历元素就优先 foreach。

## for 与 while

for 的三段式结构,是我最先记牢的。为了验证理解,我自己写了个输出 1 到 10 的小例子:

```csharp
// 输出 1 到 10 的整数
void Start()
{
    for (int i = 1; i <= 10; i++)
    {
        Debug.Log(i);
    }
}
```

写的时候我特意盯着那个 `i <= 10`:要是手滑写成 `i < 10`,10 就永远等不到了。这也让我联想到讲义里从 100 输出到 148 的例子,它写的是 `i < 149`——这种"小于号配上限"的写法最容易在边界上栽跟头。

讲义里的经典案例是算 1 加到 100 的和,我也照着敲了一遍:

```csharp
void Start()
{
    int sum = 0;                    // 累加结果先清零
    for (int i = 1; i <= 100; i++)  // i 从 1 一路走到 100
    {
        sum += i;                   // 等价于 sum = sum + i
    }
    Debug.Log("1+2+...+100 = " + sum);
}
```

跑出来是 5050,和自己手算的一致,心里踏实不少。后来做随堂作业"求 1~100 奇数和",我又试着用 while 写了一遍:while 没有自带"计数"那一格,初始值、条件、`i += 2` 全得自己拆开放。同样的逻辑两种写法都能表达,差别只是谁把循环变量管得更紧——for 管得牢,while 更自由但更容易漏句。

## break、continue 与 do-while

这两个关键字我一开始总搞混,其实作用完全不同:break 是"到此为止",整个循环直接终止;continue 是"这次不算",跳过当前这一轮,循环照常往下走。讲义的两个例子我各跑了一遍:在 `i == 5` 时 break,结果只输出 0 到 4,5 以及后面的数字全没了;在 `i == 2` 时 continue,输出变成 0、1、3、4,只有 2 被跳过。

do...while 的特别之处在于"先斩后奏",我用讲义那个从 5 往下减的例子验证了一下:

```csharp
int a = 5;
do
{
    Debug.Log("a = " + a); // 先执行,输出 5、4
    a--;
} while (a > 3);           // 再判断,注意这行末尾有分号
```

一开始我没想通它和 while 的差别,把两个例子放在一起对比就明白了:while 是"先看条件再做事",条件不满足就一次也不跑;do...while 是不管三七二十一先跑一次,之后才看条件脸色。

## 容易踩的坑

把讲义反复看了几遍、自己又敲错几回之后,我记下了这几个高频翻车点:

- **忘记更新循环变量**:循环体里少了让计数器变化的那一句(比如 `i++`),条件永远满足,直接变成死循环;
- **条件一开始就不成立**:讲义里 while 的例子把 a 初始化为 0,条件却写的 `a > 3`,结果一次都没执行——别指望 while 会"先跑一次",那是 do...while 的活儿;
- **i 的边界差一**:条件写 `i < 10` 时 i 最大只到 9,想包含 10 得写 `i <= 10`,讲义输出 100 到 148 用的就是 `i < 149`,稍不留神就多跑或少跑一轮;
- **break 和 continue 的语义记混**:它俩常和 if 写在一起,但 break 跳出的是所在的那层循环而不是 if,continue 跳过的只是当前这一次迭代,循环并不会停。

## 小结与我的思考

这一节学完,我最大的收获不是背下了四种循环的语法,而是开始有了"选型"意识:看到"把每个元素过一遍"想 foreach,看到"数到第 N 次"想 for,看到"看情况继续"想 while,do...while 则是 while 的兜底变体。语法本身不难,难的是把它嵌进真实需求里想清楚。

随堂作业故意让同一道"1~100 奇数和"分别用 for 和 while 写两遍,我当时觉得有点重复,做完才发现这是最有效的对比练习——两段代码逻辑一模一样,差别只在循环变量的更新写在哪儿,亲手写过一次,印象比看十遍讲义都深。往后在 Unity 里写游戏逻辑,这种"批量处理"的思想大概会经常冒出来,我现在的任务就是把小例子都跑明白、把坑都记牢,免得将来写出一段转不停的死循环。
