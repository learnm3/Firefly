## 1. 重心坐标（Barycentric Coordinates）：三角形插值的基础

### 1.1 为什么需要插值

顶点处有明确指定的值（纹理坐标、颜色、法线……），但三角形**内部**每个点都需要一个平滑过渡的值——不可能给每个像素都手写属性。所以需要一套"用三个顶点推内部任意点"的机制。

```
为什么插值？        插值什么？           怎么插值？
顶点指定值   →   纹理坐标/颜色/法线   →   重心坐标
```

### 1.2 定义：用三个顶点的加权和表示点

平面上任意一点 (x, y)，只要它**在三角形所在平面内**，都可以写成：

```
(x, y) = αA + βB + γC       其中 α + β + γ = 1
```

这三个权重 (α, β, γ) 就叫**重心坐标**。判定点在三角形内：**三个坐标都非负**（都 ≥ 0）。

### 1.3 特殊点：一眼看出重心坐标

- 顶点 A 的重心坐标 = **(1, 0, 0)**（全权重给 A 自己）
- 顶点 B = (0, 1, 0)，顶点 C = (0, 0, 1)
- 质心（三条中线交点）= **(1/3, 1/3, 1/3)**——每个顶点平均分

### 1.4 几何视角：面积比

重心坐标还可以看成**面积占比**：

```
α = A_A / (A_A + A_B + A_C)      // 对边 BC 方向上的子三角形面积占比
β = A_B / (A_A + A_B + A_C)
γ = A_C / (A_A + A_B + A_C)
```

即：α 越大，点越"靠近 A 对面的边"；点在 A 上时 α=1、β=γ=0。直觉上：**重心坐标度量"点离哪个顶点更近、有多近"**。

### 1.5 计算公式

不用每次画三角形量面积，直接代入坐标算（以二维为例）：

```
α = [ -(x - xB)(yC - yB) + (y - yB)(xC - xB) ] / [ -(xA - xB)(yC - yB) + (yA - yB)(xC - xB) ]
β = [ -(x - xC)(yA - yC) + (y - yC)(xA - xC) ] / [ -(xB - xC)(yA - yC) + (yB - yC)(xA - xC) ]
γ = 1 - α - β
```

**记忆技巧**：分母是"整个三角形的两倍面积"（叉积的模），分子是"点 P 与对应边围成的子三角形两倍面积"——本质就是把 1.4 的面积比公式用叉积写开。第 5 课 inside 判定用三叉积同号，这里用面积比，**同一套叉积思想**。

### 1.6 用重心坐标插值顶点属性

有了 (α, β, γ)，任意顶点属性 V（位置、纹理坐标、颜色、法线、深度、材质参数……）都可以线性插值：

```
V = αVA + βVB + γVC
```

### ⚠️ 1.7 关键陷阱：重心坐标在投影下不不变！

```
Barycentric coordinates are NOT invariant under projection!
```

**插值必须在三维空间做，投影之后的重心坐标 ≠ 原始重心坐标。** 换句话说：不能先投影三角形到屏幕、在屏幕上算 (u,v) 重心坐标再去查纹理。正确做法是：**在 3D 中先算好重心坐标（或插值属性），再随顶点一起投影**。

> 面试点：这就是为什么透视正确纹理映射（perspective-correct interpolation）需要特殊处理——屏幕空间的线性插值在透视下不是正确的 3D 线性插值（第 10 课/作业 4 会接触）。

## 2. 纹理应用：最简单的漫反射贴图

第 8 课的核心流程，这里落成伪代码：

```
for each rasterized screen sample (x, y):
    (u, v) = evaluate texture coordinate at (x, y)   // 用重心坐标插值！
    texcolor = texture.sample(u, v)
    set sample's color to texcolor                    // 通常作为漫反射 albedo kd
```

- (u, v) 的插值：每个像素中心的重心坐标 → `u = αuA + βuB + γuC`
- 取到的纹理颜色通常喂给 Blinn-Phong 的漫反射系数 kd

## 3. 纹理太小怎么办：纹理放大与双线性插值

### 3.1 问题：纹素比像素还大

纹理分辨率不足时（例如 8×8 纹理贴到 800×600 屏幕），屏幕上相邻像素可能采样到**同一个纹素**，出现明显"马赛克"。三种插值策略：

| 方法 | 做法 | 效果 |
|---|---|---|
| **Nearest**（最近邻） | 取最近的纹素颜色 | 最快，但块状感明显（马赛克） |
| **Bilinear**（双线性） | 周围 4 个纹素两两线性插值 | 平滑，性价比高，最常用 |
| **Bicubic**（双三次） | 周围 16 个纹素做三次插值 | 更平滑，但计算量大 |

### 3.2 双线性插值：两次 1D 线性插值

要在纹理坐标 (x, y) 处取样，取周围 4 个采样点 u00、u10、u01、u11（左下、右下、左上、右上），加上小数偏移 (s, t)：

```
1D 线性插值:  lerp(x, v0, v1) = v0 + x(v1 - v0)

第一次（水平方向，两个辅助值）:
    u0 = lerp(s, u00, u10)     // 下边两点
    u1 = lerp(s, u01, u11)     // 上边两点

第二次（垂直方向，收尾）:
    f(x, y) = lerp(t, u0, u1)
```

**顺序先水平后垂直**，所以叫"双"线性：先用 s 把左右两对点各插成一个，再用 t 把这两个插成一个。

## 4. 纹理太大怎么办：点采样失效，走向范围查询

### 4.1 问题：混叠（锯齿 + 摩尔纹）

纹理很大时（高频细节多），远处一个屏幕像素"脚掌"（footprint）覆盖纹理上**一大片**区域。点采样只取其中一个纹素，高频细节被严重欠采样 → 锯齿、摩尔纹、闪烁。

### 4.2 超采样能救吗？能，但太贵

对每个像素做 512× 超采样可以正确抗锯齿——但计算量爆炸，实时渲染不现实。

### 4.3 换个思路：不采样，直接求平均

问题本质：**像素覆盖的是一个纹理区域，需要的是这片区域的平均值，而不是一个点**。

```
点查询（Point Query）:    采样单个纹素          ← 会混叠
范围查询（Range Query）:  求区域内平均值         ← 我们真正需要的
```

不同像素在不同距离/角度下，footprint 大小不一，需要一个能快速回答"任意正方形区域平均值"的数据结构 → **Mipmap**。

## 5. Mipmap：快速近似正方形范围查询

### 5.1 是什么：多层预过滤纹理金字塔

(L. Williams, 1983) 把纹理逐层减半分辨率，预先生成一整套：

```
Level 0 = 128×128  ← 原纹理
Level 1 =  64×64
Level 2 =  32×32
...
Level 7 =   1×1
```

"mip" 来自拉丁语 "multum in parvo"，意为"小空间里装很多东西"。每一层都是下一层的平均（预过滤），所以**查询某一层 = 直接拿到一个区域的近似平均**。

### 5.2 存储开销：只有原来的 1/3

等比数列 1 + 1/4 + 1/16 + … = 4/3。多花 **33%** 存储，换来任意范围查询，非常划算。

### 5.3 怎么选层：计算 Mipmap Level D

用**相邻屏幕采样点的纹理坐标**估算像素在纹理空间的"脚掌"大小：

```
L = max( √((du/dx)² + (dv/dx)²),   √((du/dy)² + (dv/dy)²) )
D = log2 L
```

- du/dx、dv/dx：屏幕水平方向相邻像素的纹理坐标变化量（水平脚掌尺寸）
- du/dy、dv/dy：垂直方向变化量
- 取两者较大值，再取 log2，得到应查询的层级 D
- D 越大 = 像素覆盖的纹理区域越大 = 需要更模糊的层

### 5.4 三线性插值（Trilinear）：让层间也平滑

只查整数层 D 会在层间跳变（可视化会出现明显的层切换线）。**三线性插值**：

```
在 Level D 做双线性插值 → 结果1
在 Level D+1 做双线性插值 → 结果2
用连续 D 的小数部分对结果1、结果2 做线性插值 → 最终颜色
```

即"双线性 ×2，再对层做一次线性"= 三线性。纹理管线默认方案，硬件直接支持。

## 6. Mipmap 的局限与各向异性过滤

### 6.1 问题：过度模糊（Overblur）

斜视表面（如地面透视）的像素 footprint 是**狭长矩形甚至平行四边形**，不是正方形。Mipmap 只能查正方形区域，取较大边 → 把短边方向也模糊掉 → **过糊**。

```
超采样(正确参考)          Mipmap 三线性              各向异性过滤
清晰，代价极高            远处地面过糊                远近都清晰
```

### 6.2 各向异性过滤（Anisotropic Filtering）

- **Ripmaps / Summed Area Tables**：按"宽 × 高"分别预过滤，可以查**轴对齐矩形**区域——能覆盖大部分斜视情况（游戏里的 4x/8x/16x 各向异性过滤就是这类）；
- **EWA 过滤**（Greene & Heckbert '86）：多次查询 + 加权平均，能处理**任意不规则（含斜对角）footprint**，质量最高但更贵。

## 7. 公式速查卡

| 名称 | 公式 / 规则 |
|---|---|
| 重心坐标 | (x,y) = αA + βB + γC，α+β+γ=1；三角形内 ⇔ 全非负 |
| 顶点/质心 | A=(1,0,0)，质心=(1/3,1/3,1/3) |
| 面积视角 | α = A_A / (A_A+A_B+A_C)（子三角形面积占比） |
| 属性插值 | V = αVA + βVB + γVC（位置/uv/颜色/法线皆可） |
| 双线性插值 | u0=lerp(s,u00,u10)，u1=lerp(s,u01,u11)，f=lerp(t,u0,u1) |
| Mipmap 层级 | L = max(√((du/dx)²+(dv/dx)²), √((du/dy)²+(dv/dy)²))，D = log2 L |
| Mipmap 开销 | 仅 +33% 存储（1+1/4+1/16+…=4/3） |
| 三线性插值 | D、D+1 两层双线性结果再按 D 小数部分线性混合 |

## 9. 高频易错点

- **重心坐标不随投影不变**：屏幕空间算的插值 ≠ 3D 正确插值，透视纹理映射要特殊处理；
- 重心坐标插值的是**顶点属性**，不是直接插值 (u,v) 本身后当颜色用——先插 uv 再查纹理；
- 双线性插值是"水平两次 + 垂直一次"，不是简单平均 4 个纹素；
- Mipmap 查的是**正方形**区域，斜视会过糊——所以有各向异性过滤；
- D = log2 L 的 L 要取水平/垂直脚掌的**较大者**，否则垂直方向细节会混叠；
- Nearest 用于放大出马赛克、点采样用于缩小出摩尔纹——同一个欠采样问题，两个方向的表现。
