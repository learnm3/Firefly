这节课我写出了在 Unity 里的第一段代码:新建脚本、挂到物体上、点运行,在控制台看到自己打印的那行字,感觉它真的"听懂"我了。整节课就三件事:类与方法的结构、Unity 日志输出、格式规矩。

## 类与方法,我这样理解

最初我以为"类"很玄,听完觉得它更像一个装着代码的盒子:前面可放访问修饰符(`public`、`protected`、`private`,不写默认私有),接着是关键字 `class` 和类名,花括号里装成员变量与方法。类本身不干活,更像模板。

真正干活的是方法——把语句组织起来完成一件事,完整写法是"访问修饰符 + 返回值类型 + 方法名 + 圆括号(放参数)+ 方法体"。我一开始不懂 `void`,后来想明白:要不要交结果由返回值类型决定,要交就写 `int`,再用 `return` 送回去;不交就写 `void`。

方法还要"被调用"才有用:静态方法用`类名.方法名`,普通方法用`对象.方法名`。老师提醒:新人阶段把精力放在方法内部语法上。

## 在 Unity 里输出 Hello World

到 Unity 里写脚本,类要继承 `MonoBehaviour`——它装着 `Awake`、`Start`、`Update` 等生命周期方法,Unity 到点自动调用,名字不能乱改。我的第一个脚本:

```csharp
using UnityEngine;

public class HelloWorld : MonoBehaviour
{
    // Start 在第一次 Update 前被调用一次,适合做初始化
    void Start()
    {
        Debug.Log("Hello World");        // 普通日志,控制台显示白色
        Debug.LogWarning("这条是警告");  // 警告日志,显示黄色
        Debug.LogError("这条是错误");    // 错误日志,显示红色
    }
}
```

注释写给人看、不影响运行:单行用 `//`,多行用 `/* */` 包住。我把一行日志注释掉再运行,那条输出果然消失,注释真的会"屏蔽"代码。

## 写代码的"格式规矩"

写 C# 和写中文最大的差别,是对格式极其较真,讲义规矩我总结成口诀:

- 全部英文半角输入,全角符号直接编译报错。
- 完整语句用英文分号收尾。
- 定义、调用方法都要圆括号,参数放里面。
- 类和方法的主体放进成对的花括号。
- 静态方法用`类名.方法名`,普通方法用`对象.方法名`。

光看容易忘,故意错一遍就记住了。

## 容易踩的坑

我踩过或差点踩的坑:

1. 分号打成中文全角,编译报错,半天才发现是输入法没切回英文。
2. 以为"写完了"就换行,忘了分号,编译器立刻报缺分号。
3. 括号只写一半,后来我改成先补一对空的再往里填。
4. 多行注释少写收尾,或和 `//` 混用,会把后面代码"吞"掉。
5. `Start` 拼错,运行毫无反应,我还以为脚本没挂上——Unity 靠名字认方法。

## 小结与我的思考

类以 `class` 开头,花括号包住成员;方法讲究修饰符、返回值、方法名、参数、方法体;日志认准 `Debug.Log` 三个;全程英文半角,分号、括号不能乱。底子打牢,学变量、运算符时才不会被编译错误打断。

我还留着个疑问:`Debug.Log` 按`类名.方法名`调用,应该就是讲义说的静态方法,可为什么有的方法不用对象就能调?老师说 `static` 后面才讲,我把它记进了待办清单。
