这节 C# 入门课(Unity 2023.2.20f1c1 + Visual Studio 2022)在讲完变量之后,紧接着抛出了"常量"这个概念。我第一反应是有点懵:变量就是"会变的量",再来一个"不会变的量",不是多此一举吗?课后我把讲义里的例子挨个敲了一遍,又想了想实际项目里为什么需要它,才慢慢转过弯来——常量并不是变量的对立面,而是一种特殊的变量,专门用来装那些从头到尾都不该变的值。

## 常量,我这样理解

讲义给的定义是:常量是一种特殊的变量,程序运行期间它的值不可以改变。定义不难记,"为什么需要它"才值得想,我自己总结了三点。一是防误改:本该固定的值若写成普通变量,等于给代码留了"以后偷偷改掉"的机会;声明成常量后谁再赋值,编译器当场报错,不会拖到游戏运行时才暴露。二是含义清晰:看到 MAX_PLAYER_COUNT 这种全大写名字,不翻注释也知道它是写死的配置。三是好维护:版本号这类值以后要更新,只改声明那一行就够了。讲义说常量常用来定义 π、版本号这类不会改变的值,我现在觉得要反过来读:正因为这些值不该变,才值得用常量把它们"焊死"。

## 怎么声明和使用

用法一句话就能说清:在声明前加 const 关键字,并且当场给初值,语法是 `const 类型 常量名 = 值;`。我在 Unity 里写了段验证用的小脚本:

```csharp
using UnityEngine;

// 语法:const 类型 常量名 = 值;声明时必须初始化
public class GameConfig
{
    public const int MAX_PLAYER_COUNT = 4;       // 一局最多 4 名玩家
    public const double PI = 3.14159;            // 圆周率这类固定值
    public const string GAME_VERSION = "0.1.0";  // 版本号,命名习惯全大写
}

public class PlayerSpawner : MonoBehaviour
{
    private void Start()
    {
        // 常量默认是静态的,必须通过类名访问,而不是实例
        Debug.Log(GameConfig.GAME_VERSION);      // Console 输出:0.1.0
        Debug.Log(GameConfig.MAX_PLAYER_COUNT);  // Console 输出:4
    }
}
```

这段代码让我记牢了三件事:常量名约定全大写、单词间用下划线,和驼峰命名的变量一眼就能区分开;常量默认是静态的,只能通过类名访问,我一开始想着用实例去访问,怎么都不对劲;并不是什么值都能当常量,只有编译时就能确定的值才行,具体限制我放到"坑"那节里细说,踩过一次印象更深。

## 常量 vs 变量

光记概念容易混,我把两者并排对比,整理成下面这张小表:

| 对比项 | 变量 | 常量 |
| --- | --- | --- |
| 可否修改 | 声明之后可以反复赋值 | 一旦定义,运行期不能再改 |
| 什么时候赋值 | 可以先声明、后赋值 | 声明的同时必须初始化 |
| 命名习惯 | 一般驼峰,如 maxCount | 约定全大写,如 MAX_COUNT |
| 访问方式 | 通过变量名访问 | 默认静态,通过类名访问 |

比完我最大的感受是:变量给代码"灵活性",常量给代码"确定性"——用哪个,本质上就是在回答"这个值到底允不允许变"。

## 容易踩的坑

结合讲义里的错误示例和随堂作业的错题,我整理了四条最容易踩的坑:

1. **试图给常量重新赋值。** 作业里有个方法写了 `Rate = 0.15;`,想给常量赋新值,这一行编译时就会报错;正确做法是声明时就写好初值,如 `const double Rate = 0.15;`。
2. **声明时不初始化。** 比如写 `const double Pi;` 想着之后再赋值,但常量要求"声明即初始化",编译器不接受这种写法。
3. **拿不允许的值定义常量。** 只有编译时可确定的值才行:基本类型、string、枚举可以;`const DateTime Now = DateTime.Now;` 属于运行时计算,`List` 这类引用类型也不行,全都会编译报错。
4. **命名太随意。** 课上约定常量全大写、下划线分词,若照变量的驼峰风格命名,代码一多就分不清哪些值能改、哪些不能改。

## 小结与我的思考

这节知识点串起来就一句:用 const 声明常量,声明时必须初始化,只能放编译时可确定的值,一旦定义便不可修改;常量默认静态、通过类名访问,命名习惯全大写。

语法之外,我更想琢磨的是"什么时候该用常量"。像讲义举的 π、版本号,天然就不该变;我自己代码里的玩家数量上限 MAX_PLAYER_COUNT 也是,与其散落各处写死,不如集中定义,以后想调只动一行。我想这大概是编程习惯的分水岭:动手前先问自己一句"这个值会不会变",不会变,就放心交给常量。
