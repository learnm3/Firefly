这周的 C# 课讲数组,光听内容觉得不多,不就是"把一堆同类型的数据排在一起"嘛。可真轮到自己动手,在 Unity 2023.2 里配着 Visual Studio 写代码时,报错、改错、越界、来回查,才发现上课"听懂了"和"会用"之间差着一次完整的复习。这篇就当我的课后理解笔记,把我是怎么想明白数组、怎么写、又踩了哪些坑,顺着自己的思路记一遍。

## 数组,我这样理解

如果要我给完全没学过的人解释,我会说:数组就是一排编好号的储物柜,柜子在开出来之前长度就定死了,之后想再加一格?不行。而且每个格子的规格必须一样,整型数组里塞不进字符串,这叫"强类型"。这些柜子在内存里是紧挨着放的,想取第 i 格不用挨个翻,拿首地址算一下位置就到,所以按下标访问特别快。最反直觉的是编号从 0 开始:第一个元素是 `arr[0]`,不是 `arr[1]`。我一开始老想从 1 数,后来把下标理解成"离起点往后走了几步",心里才顺了。想明白了这些,再回头看"定长、内存连续、强类型、访问效率高"这几个特点,就不只是背概念了。

## 声明、初始化与遍历

声明和初始化记三行容易乱,复习后我觉得可以浓缩成一句话:要么只给长度、元素自动拿默认值,要么在声明时把初值直接列出来。

```csharp
// 方式一:只指定长度,元素自动填默认值(这里是 5 个 0)
int[] arr1 = new int[5];

// 方式二:一边 new 一边把初值写全
int[] arr2 = new int[] { 1, 2, 3, 4 };

// 方式三:简化写法,让编译器推断类型,最常用
double[] arr3 = { 9.9, 15.5, 20.0 };
```

"默认值"这条规则我一开始没当回事,复习才发现是个雷:值类型数组自动拿到对应默认值(int 是 0、bool 是 false),而引用类型数组——比如 `string[]`,new 出来之后每个位置是 null,并不是空字符串,处理方式完全不同。

访问和遍历,讲师拿"班里成绩"举的例子我印象最深,课下我在 Unity 里敲了一遍:

```csharp
int[] scores = { 85, 90, 78, 92 };   // 4 个成绩

scores[1] = 95;          // 修改第 2 个(下标 1):数组变成 { 85, 95, 78, 92 }

// for:下标自己管,适合要"第几个"的场合
for (int i = 0; i < scores.Length; i++)
{
    Debug.Log(scores[i]);
}

// foreach:只负责"拿下一个",适合纯遍历
foreach (int score in scores)
{
    Debug.Log(score);
}
```

## 多维数组与常用方法

一维数组像一行柜子,二维就像一张表格,得用两个下标定位:先第几行、再第几列。语法上写 `int[,]`,中间用逗号表示维度。

```csharp
// 3 行 2 列的二维数组
int[,] grid = new int[3, 2] { { 1, 2 }, { 3, 4 }, { 5, 6 } };

Debug.Log(grid[1, 0]);   // 3,即"第 2 行第 1 列"

for (int r = 0; r < grid.GetLength(0); r++)      // GetLength(0) 是行数
    for (int c = 0; c < grid.GetLength(1); c++)  // GetLength(1) 是列数
        Debug.Log(grid[r, c]);
```

一维数组用 `Length` 就能拿到总个数,二维就得靠 `GetLength` 分别取每个维度的长度,这个差别我在写双重循环时才真正体会到。三维数组语法上再加一层逗号、再套一层花括号,类似"2 层、每层 2×2",目前我用得少,先知道有这回事。常用成员我整理成了一张表,再配一个讲师课上"5 个学生成绩"的案例:

| 成员 | 作用 | 我的备注 |
|---|---|---|
| Length | 一维数组元素的总个数 | 常直接当 for 的上界 |
| GetLength(维度) | 指定维度的长度 | 二维里 0 是行、1 是列 |
| Array.Sort(数组) | 升序排序 | 原地修改,没有新数组返回 |
| Array.Reverse(数组) | 反转元素顺序 | 排完序再反转,就得到降序 |
| Array.IndexOf(数组, 值) | 找元素首次出现的下标 | 找不到时返回 -1 |

```csharp
int[] scores = { 80, 75, 90, 85, 70 };   // 5 名学生的成绩

Array.Sort(scores);               // 升序排好:70 75 80 85 90
foreach (int s in scores) Debug.Log(s);

int total = 0;                    // 累加求和
foreach (int s in scores) total += s;
Debug.Log("总分:" + total);       // 总分:400
```

## 容易踩的坑

把这一路的报错和翻车攒一攒,基本就是下面几条,都是我拿讲义里的例子亲手验证过的:

1. 下标越界直接崩:长度 5 的数组合法下标只有 0~4,写 `scores[5]` 会抛越界异常,运行时直接出错,所以 for 的条件要写 `i < Length`,而不是 `i <= Length`。
2. 从 0 开始导致的"差一位":想取最后一个元素,下标是 `Length - 1`;写成 `Length` 就又越界了,这种错最隐蔽,写循环边界时得格外清醒。
3. foreach 改不了元素:循环变量只是每个元素的"复印件",编译器根本不允许给它赋值;想改数组里的值,老老实实用 for 加下标。
4. 引用类型数组默认全是 null:`new string[3]` 之后每个元素都是 null,不先赋值就拿来用很容易出问题;而值类型数组会安全地拿到默认值。
5. Array.Sort、Array.Reverse 都是原地操作:它们不返回"处理好的新数组",而是直接改原数组。如果之后还用得到原始顺序,排序前就得想好这一点。

## 小结与我的思考

现在回头看,数组的特点就四个词:定长、强类型、内存连续、从 0 开始。用法也顺了:三种初始化本质是"分配长度"和"填初值"的不同组合;遍历要么 for(要下标、要改值),要么 foreach(只读);多维数组记得用 GetLength 逐维取长;Sort、Reverse、IndexOf 能省掉不少手写循环。真正让我惦记的是另一件事:数组"长度固定"在游戏里挺别扭——比如玩家的数量要运行时才知道,甚至可能中途变化,总不能一上来就把数组开得特别大吧?讲师讲到这儿卖了个关子,说后面会有更灵活的容器,我挺好奇它和数组比,除了"能变长"还有哪些不一样,这也是我下次上课最想听的部分。
