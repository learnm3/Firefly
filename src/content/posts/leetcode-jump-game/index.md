## 题目回顾

[LeetCode 55. Jump Game](https://leetcode.cn/problems/jump-game/) — 难度：中等

**给你一个非负整数数组 `nums`，你最初位于数组的第一个下标。数组中的每个元素代表你在该位置可以跳跃的最大长度。判断你是否能够到达最后一个下标。**

```
输入：nums = [2,3,1,1,4]
输出：true
解释：先跳 1 步到下标 1，再跳 3 步到达终点
```

**直观理解**：每个格子告诉你"最多能跳多远"，判断能不能从起点跳到终点。

---

## 游戏场景：这道题在游戏里到底干什么用？

### 场景一：关卡跳跃可达性检查（平台跳跃 / 动作游戏）

> 关卡设计时，策划在场景里放了一排平台，每个平台标着"从这能跳到的最大平台数"。问：**玩家能不能从起点平台一路跳到终点平台？** 这就是关卡设计师做"流程可达性校验"的核心问题。

```
平台序列（每格 = 从这能跳最远几个平台）：
  [2, 3, 1, 1, 4]
   起点           终点
   能跳2个  能跳3个 ...

   → true（先到第2个，再直接跳3个到终点）
```

**这是「跳跃游戏」的直译**。关卡设计工具（Unreal 的关卡校验、平台跳跃的路线检测）都要做这类"可达性检查"——防止设计出玩家到不了终点的关卡。

> **面试延伸**：真实关卡可达性更复杂——要考虑跳跃高度、攀爬、二段跳（不是简单的"能跳 N 格"）。但**可达性的核心判断逻辑**（维护最远能到哪）是一样的。能说清"实际游戏里是 2D/3D 可达域，但一维版本的判定思想通用"，面试官会认可。

### 场景二：角色攀爬/跳跃判定（动作游戏）

> 角色面对一堵墙或一条沟，系统要判断"当前速度 + 跳跃力能不能过去"。把障碍物序列看成数组，每个位置的可达距离 = 跳跃能力——判断能否越过整条障碍。

### 场景三：机关连跳 / 跑酷路线（跑酷游戏）

> 跑酷游戏里，每个跳板标注"从这起跳能越过几个障碍"。验证整条跑酷路线是否可行——保证玩家不会卡死在半路。

### 场景四：资源/节点可达性（开放世界）

> 开放世界地图上，传送点之间有距离限制。判断"从出生点能否到达所有关键区域"——用跳跃游戏的可达性思想做地图连通性校验。

## 解法分析

### 解法一：贪心 — O(n) ⭐ 标准答案

**核心思想**：不真的跳每一步，而是**维护"当前能到达的最远下标"**。遍历每个位置，如果当前位置可达（`i <= maxReach`），就更新最远可达 = `max(maxReach, i + nums[i])`。只要最远可达覆盖终点，就能到达。

```cpp
bool canJump(vector<int>& nums) {
    int maxReach = 0;   // 当前能到达的最远下标
    for (int i = 0; i < nums.size(); i++) {
        if (i > maxReach) return false;   // 当前位置都到不了 → 失败
        maxReach = max(maxReach, i + nums[i]);   // 更新最远可达
        if (maxReach >= nums.size() - 1) return true;   // 已覆盖终点
    }
    return true;
}
```

**为什么正确（贪心 + 覆盖）**：

```
nums:  [2, 3, 1, 1, 4]
i=0:   maxReach = max(0, 0+2) = 2     ← 能到下标2
i=1:   maxReach = max(2, 1+3) = 4     ← 能到下标4（终点！）→ true
```

- **关键洞察**：从位置 i 出发能到达 `[i, i+nums[i]]` 的**所有位置**（不是只能跳 nums[i] 整步）——所以"能到的最远点"就是 i+nums[i]，中间的都可达
- 遍历时只要 `i <= maxReach` 就说明 i 可达，可以继续向前探索
- **不用真的模拟跳跃**：因为每个位置的可达范围是连续的，维护右边界即可

> **面试必答要点**：
> 1. **为什么能贪心？** —— 从 i 能跳到 `[i, i+nums[i]]` 连续区间，所以只需维护最远右边界，不用模拟具体跳法
> 2. **终止条件**：`i > maxReach`（卡住了）或 `maxReach >= 末尾`（到达）
> 3. 空间 O(1)，时间 O(n)——比 DFS/BFS 模拟高效得多

### 解法二：反向贪心（另一种写法，理解用）

从终点往前找"能跳到终点的最左位置"，逐步回推：

```cpp
bool canJump(vector<int>& nums) {
    int target = nums.size() - 1;   // 目标位置（从终点开始回退）
    for (int i = nums.size() - 2; i >= 0; i--) {
        if (i + nums[i] >= target) {
            target = i;   // 位置 i 能跳到当前目标，回退目标
        }
    }
    return target == 0;   // 最终目标能否回退到起点
}
```

**思想**：如果 `i` 能跳到当前"目标位置"，那 `i` 之前只要能到 `i` 就能间接到终点——目标不断前移，最后看能否到起点。两种写法等价，掌握一种即可。

## 与游戏开发的更深联系

### 可达性思想在游戏中的位置

| 游戏系统 | 可达性的体现 |
|---|---|
| **关卡设计校验** | 平台跳跃路线可达性（本题直译） |
| **地图连通性** | 传送点/区域可达范围检查 |
| **寻路预处理** | 判断目标是否在可达域内，避免无效 A* |
| **技能释放距离** | 目标是否在技能覆盖范围内（区间判定） |
| **资源加载预判** | 玩家是否可能到达某区域（决定是否预加载） |

**更深一层**：UE 的 **NavMesh（导航网格）** 寻路前，会先做"可达性粗筛"——判断目标点是否在可达区域内，避免对不可达目标跑完整寻路。这和一维"跳跃游戏"维护可达边界的思路一脉相承（只是扩展到 2D/3D）。

### 面试怎么答"贪心在游戏里用过吗"

**推荐回答**：

> 「我理解这道题的贪心是**维护可达边界**：从 i 能跳到连续区间 [i, i+nums[i]]，所以只需记录最远点，不用模拟每步。游戏里类似的"先判断可达再行动"很常见——比如**寻路前先做可达性粗筛**（目标在不可达区域就直接放弃，省掉 A* 开销），还有**技能施放距离判断**（目标是否在覆盖区间内）。我做 UE 项目时，加载策略也会先判断玩家可能到达的区域范围。」

## 总结：这道题你该带走什么

1. **贪心"维护最远可达"**要能独立写出（O(n) 解法）
2. 理解"从 i 可达连续区间"是贪心正确性的关键
3. 能举出游戏场景（关卡可达性、寻路粗筛）
4. 知道正向贪心 + 反向贪心两种写法
5. 变体题（跳跃游戏 II）至少知道思路

把代码放进 IDE，用 `[2,3,1,1,4]`、`[3,2,1,0,4]`、`[0]` 三个用例跑一遍——第二个用例到不了终点（0 卡住），体会"维护可达边界"的精妙。
