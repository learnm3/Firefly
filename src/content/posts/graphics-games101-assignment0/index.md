## 二、环境搭建：VirtualBox + Ubuntu 虚拟机

### 2.1 课程官方方案

GAMES101 官方提供了一台配好环境的 Ubuntu 18.04 虚拟机（`.vdi` 虚拟磁盘），里面已经装好了 `g++`、`cmake`、`OpenCV`、`Eigen`。流程是：

1. 安装 **VirtualBox**
2. 新建虚拟机（类型 Linux / Ubuntu 64-bit，内存 4GB）
3. 硬盘选 **"使用已有的虚拟硬盘文件"**，挂载课程给的 `.vdi`
4. 启动，登录

> **坑 0：磁盘别选错。** 新建向导里默认选中的是"**现在创建虚拟硬盘**"，如果没注意就会新建一个 2MB 的空盘，系统自然启动不了。一定要选"**使用已有的虚拟硬盘文件**"。

> **坑 0.5：VirtualBox 版本。** 课程资料里附带的是 2020 年的 VirtualBox 6.1.4，在 **Windows 11** 上大概率装不上或跑不起来（6.1.x 直到 6.1.28 才支持 Win11）。直接去官网下最新的 7.x 版本。

### 2.2 坑 1：开机黑屏 —— 显卡控制器不兼容

虚拟机建好后一开机就**黑屏**。原因不是启动模式问题（可以用脚本确认磁盘是 MBR/BIOS 而非 GPT/EFI），而是**显卡控制器不兼容**：

- 新建虚拟机默认用 `VMSVGA`，但 2020 年的老 Ubuntu（4.18 内核 + 旧驱动）认不出它
- **解决办法**：把图形控制器改成 `VBoxSVGA`（或更老更兼容的 `VBoxVGA`）

```bash
# 命令行方式（虚拟机需先关机）
VBoxManage modifyvm "GAMES101" --graphicscontroller vboxsvga --vram 128 --accelerate3d off
```

> ⚠️ 注意：**不要直接编辑 `GAMES101.vbox` 配置文件**。VirtualBox 服务会把内存里的配置重新写回，你的改动会被静默覆盖。要用 `VBoxManage` 或图形界面的设置。

判断"磁盘是 BIOS 还是 EFI"的小技巧（读到 VDI 第一个扇区）：

```python
# MBR 的签名是 0x55AA 位于第 510 字节；GPT 是 "EFI PART" 位于第 512 字节
mbr = sector[510:512] == b'\x55\xaa'
gpt = sector[512:520] == b'EFI PART'
```

### 2.3 坑 2：增强功能（Guest Additions）

不装增强功能（Guest Additions）会怎样？

- ❌ 宿主机 ⇄ 虚拟机**不能复制粘贴**
- ❌ **共享文件夹不能用**
- ❌ 拖放不能用
- ❌ 分辨率不能自适应

**安装步骤**：

```bash
# 1. 宿主机把 GA 光盘挂上（虚拟机需关机）
VBoxManage storageattach "GAMES101" --storagectl IDE --port 0 --device 0 \
    --type dvddrive --medium "C:\Program Files\Oracle\VirtualBox\VBoxGuestAdditions.iso"

# 2. 虚拟机内执行安装（需要内核头文件，通常已装）
sudo sh /media/<用户名>/VBox_GAs_7.2.20/VBoxLinuxAdditions.run

# 3. 把用户加入 vboxsf 组，否则访问不了共享文件夹
sudo usermod -aG vboxsf <用户名>
# 4. 重启
```

安装成功的验证：

```bash
ls /lib/modules/$(uname -r)/misc/     # 应有 vboxguest.ko vboxsf.ko vboxvideo.ko
lsmod | grep vbox                     # 三个模块应处于加载状态
ls /media/sf_share                    # 共享文件夹应能列出宿主机目录
```

### 2.4 坑 3：⚠️ 千万别在共享文件夹里编译（最坑的一个）

装好共享文件夹后，很容易顺手这样干：

```bash
cd /media/sf_share/Assignment1/build
cmake ..        # ← 整个虚拟机会卡死！
```

**后果**：`cmake` 进程进入**不可中断的 D 状态**，`Ctrl+C` 杀不掉，最后只能强制重启虚拟机。内核日志会刷出：

```
INFO: task cmake:5451 blocked for more than 120 seconds.
INFO: task code:4582  blocked for more than 120 seconds.   # VS Code 也一起卡死
```

**原因**：`vboxsf`（共享文件夹）是靠宿主机转发实现的文件系统，**扛不住大量小文件 I/O**。而 cmake 正好要创建/stat 成千上万个文件。

**正确姿势**：共享文件夹**只用来传文件**，编译必须在虚拟机本地磁盘做。

```bash
# ✅ 正确流程：先拷贝到本地，再本地编译
cp /media/sf_share/pa0/main.cpp /media/sf_share/pa0/CMakeLists.txt ~/work/pa0/
cd ~/work/pa0/build && cmake .. && make && ./Transformation
```

> 💡 同理，**VS Code 直接打开共享文件夹里的项目也会卡死**。要么把项目放虚拟机本地，要么在宿主机上编辑、再同步进去。

### 2.5 附赠：用 guestcontrol 自动化操作虚拟机

装了增强功能后，宿主机可以**直接在虚拟机里执行命令、传文件**，不用再切窗口：

```bash
# 在虚拟机里执行命令
VBoxManage guestcontrol "GAMES101" run --username <用户> --password <密码> \
    --exe /bin/bash -- -c "cd ~/work/pa0/build && make && ./Transformation"

# 拷文件进虚拟机
VBoxManage guestcontrol "GAMES101" copyto --username <用户> --password <密码> \
    --target-directory /home/<用户>/work/pa0 本地文件
```

这对"宿主机写代码、虚拟机编译"的工作流非常友好。

## 三、Eigen 入门：图形学的线性代数工具库

Eigen 是纯头文件的 C++ 线性代数库（`sudo apt install libeigen3-dev`），图形学里处处都是它。

### 3.1 向量与矩阵的定义

```cpp
#include <eigen3/Eigen/Core>
#include <eigen3/Eigen/Dense>

Eigen::Vector3f v(1.0f, 2.0f, 3.0f);   // 3 维 float 向量
Eigen::Matrix3f m;                      // 3x3 float 矩阵

// 矩阵用 << 按【行】填写
m << 1, 2, 3,
     4, 5, 6,
     7, 8, 9;
```

### 3.2 基本运算

| 运算 | 写法 | 说明 |
|---|---|---|
| 向量加法 | `v + w` | 对应分量相加 |
| 向量数乘 | `v * 3.0f`、`2.0f * v` | 支持左右两种 |
| 矩阵加法 | `i + j` | 对应元素相加 |
| 矩阵数乘 | `i * 2.0f` | **注意写 `2.0f`**，`2.0` 是 double |
| 矩阵乘法 | `i * j` | **不满足交换律**，`i*j ≠ j*i` |
| 矩阵乘向量 | `i * v` | 结果是向量 |

### 3.3 ⚠️ 一个必须记住的约定

> **Eigen 的 `<<` 是「按行」填写的**，但矩阵乘法遵循的是标准数学定义。

```cpp
Eigen::Matrix3f a;
a << 1, 2, 3,      // 第 0 行
     4, 5, 6,      // 第 1 行
     7, 8, 9;      // 第 2 行
// 打印出来就是
// 1 2 3
// 4 5 6
// 7 8 9
```

## 四、核心：齐次坐标，以及为什么平移能写成"乘法"

这是作业0 真正要理解的东西。

### 4.1 先接受一个"反常"事实：2×2 矩阵做不到平移

线性变换（矩阵乘法）有条铁律：**原点必须原地不动**。

因为任何矩阵乘零向量都等于零向量：`M · (0, 0) = (0, 0)`。

但平移偏偏要**把原点挪走**：

```
(x, y) → (x + 1, y + 2)
(0, 0) → (1, 2)          ← 原点跑了
```

所以**不存在任何 2×2 矩阵能表示平移**。这正是课本把平移单独拿出来、把"线性 + 平移"合称**仿射变换**的原因。

### 4.2 齐次坐标的"骗术"：升一维，补个 1

把二维点 `(x, y)` 写成三维的 **`(x, y, 1)`**。关键就是这个多出来的 **`1`**——它是个"挂钩"，专门用来**挂常量**。

现在用 3×3 矩阵乘它，把式子**完全展开**：

```
[ 1  0  1 ]   [ x ]   [ 1·x + 0·y + 1·1 ]   [ x + 1 ]
[ 0  1  2 ] · [ y ] = [ 0·x + 1·y + 2·1 ] = [ y + 2 ]
[ 0  0  1 ]   [ 1 ]   [ 0·x + 0·y + 1·1 ]   [   1   ]
                                    ↑
                         就是这个补位的 1
                        把 dx、dy 拉进了结果里
```

**看那两份 `+ 1` 和 `+ 2`**——它们不是凭空出现的，是最后一列的系数**乘上了补位的 `1`** 才产生的。

**几何直觉**：补上 `1` 之后，点其实住在三维空间里 `z = 1` 这个平面上。那个平移矩阵在三维里是一个 **错切（shear）**——而错切是正儿八经的线性变换（原点不动），所以在三维里它就是一个普通矩阵。

> **一句话**：平移在二维不是线性的，**升到三维后它就变成了线性变换的一个特例**。

### 4.3 两个矩阵的"分工"（记住这张表）

| | 对角线（`[0][0]`、`[1][1]`） | 最后一列（`[0][2]`、`[1][2]`） |
|---|---|---|
| **作用** | **乘法** → 缩放/旋转 | **加法** → 平移 |
| **原因** | 乘的是变量 `x`、`y` | 乘的是常量 `1` |

**旋转矩阵 R(θ)**（纯旋转，最后一列必须是 0）：

```
[ cosθ  -sinθ   0 ]
[ sinθ   cosθ   0 ]
[   0      0    1 ]
```

**平移矩阵 T(dx, dy)**（= 单位矩阵，只换最后一列）：

```
[ 1  0  dx ]
[ 0  1  dy ]
[ 0  0   1 ]
```

> ## 口诀：**平移矩阵 = 单位矩阵，只把最后一列换成 (dx, dy, 1)**

### 4.4 变换顺序：`T·R` 还是 `R·T`？

题目要求"**先旋转，再平移**"。矩阵作用在**列向量**上，写成 `A · B · p` 时：

> **最右边的矩阵最先作用。**

所以"先旋转 R，再平移 T"要写成：

```
点 = T · R · p  =  T · (R · p)
                     └─ 括号里先算，R 最先作用 ✓
```

**那如果写成 `R · T` 呢？** 展开看看：

```
R·T = [ Rr  0 ] [ I   t ]   [ Rr   Rr·t ]
      [ 0   1 ] [ 0   1 ] = [ 0     1   ]
                        ↑
              平移列被"旋转"了！
```

原来是 `t`，现在变成了 `Rr·t`——**平移量被旋转了**。

用作业0 的数字对比（P=(2,1)，旋转 45°，平移 (1,2)）：

| 顺序 | 合并矩阵的平移列 | 结果 |
|---|---|---|
| 先旋转后平移 `T·R` | `(1, 2)` | **(1.7071, 4.1213)** ✅ |
| 先平移后旋转 `R·T` | `(-0.7071, 2.1213)` = `R·(1,2)` | (0, 4.2426) ❌ |

**关键结论**：

> ❌ **光看矩阵形态，是看不出"先平移还是先旋转"的**——两个矩阵长得都是 `[旋转 │ 平移]` 的样子。
> ✅ **顺序完全由你"乘法时怎么乘"决定**，区别只体现在平移列的具体数值上。

**直观理解（最好记的类比）**：想象点画在一张透明纸上——

- **先旋转后平移**：先把纸转 45°，再把纸**在世界坐标里**挪 (1,2)。位移就是实打实的 `(1,2)`。
- **先平移后旋转**：先在纸上挪 (1,2)，然后**整张纸被转了 45°**——那 `(1,2)` 的位移**也跟着转了**，变成 `R·(1,2)`。

> **一句话**：写在**左边**的变换，会"影响"写在**右边**变换产生的位移。

### 4.5 为什么非要这么绕？—— 为了"串联"

这才是齐次坐标真正值钱的地方。

**方案 A：用加法（不用齐次坐标）** —— 每个变换写成 `p' = M·p + t`：

```
p1 = R1·p0 + t1
p2 = R2·p1 + t2 = (R2·R1)·p0 + (R2·t1 + t2)
p3 = ...
```

每加一个变换，公式就更长一截，还得单独记住"平移量怎么跟着旋转"，**极易出错**。

**方案 B：用齐次坐标（统一成乘法）**：

```
M_total = M3 · M2 · M1
p_final = M_total · p0
```

**所有变换都是同一种运算**，直接乘起来就行。这就是为什么**显卡、游戏引擎、OpenGL 全都用齐次坐标**——可以把几十个变换预先合并成**一个矩阵**，之后每个顶点只做一次矩阵乘法。

## 五、完整代码

```cpp
#include <cmath>
#include <eigen3/Eigen/Core>
#include <eigen3/Eigen/Dense>
#include <iostream>

int main() {
    // ---------- 1. 点 P 的齐次坐标 (x, y, 1) ----------
    Eigen::Vector3f p(2.0f, 1.0f, 1.0f);

    // ---------- 2. 旋转矩阵（纯旋转，最后一列是 0） ----------
    // 角度必须转成弧度！sin/cos 收的是弧度
    float angle = 45.0f / 180.0f * std::acos(-1);

    Eigen::Matrix3f R;
    R << std::cos(angle), -std::sin(angle), 0,
         std::sin(angle),  std::cos(angle), 0,
         0,                0,                1;

    // ---------- 3. 平移矩阵（单位矩阵 + 最后一列放平移量） ----------
    Eigen::Matrix3f T;
    T << 1, 0, 1,      // dx = 1
         0, 1, 2,      // dy = 2
         0, 0, 1;

    // ---------- 4. 先旋转，再平移 ----------
    Eigen::Vector3f rotated = R * p;         // 先旋转
    Eigen::Vector3f result  = T * R * p;     // 再平移

    std::cout << "旋转后   = " << rotated.transpose() << std::endl;
    std::cout << "平移后   = " << result.transpose()  << std::endl;
    // 旋转后 = 0.707107  2.12132       1
    // 平移后 = 1.70711   4.12132       1

    return 0;
}
```

**编译运行**：

```bash
mkdir build && cd build
cmake ..
make
./Transformation
```

> 注意：作业0 的 `CMakeLists.txt` 里 `include_directories(EIGEN3_INCLUDE_DIR)` 少写了 `${}`（正确写法是 `include_directories(${EIGEN3_INCLUDE_DIR})`）。不过因为 Eigen 装在 `/usr/local/include` 这个**默认搜索路径**下，所以**照样能编过**。看到这行别慌。

## 六、9 个新手坑（精华总结）

### 坑 1 ⭐⭐⭐：整数除法，让角度直接变成 0

```cpp
cos(45 / 180 * acos(-1))     // ❌ 45 / 180 在 C++ 里是【整数除法】= 0！
cos(45.0 / 180 * acos(-1))   // ✅ 让除号两边至少有一个浮点数
```

**原因**：`45` 和 `180` 都是 `int`，整数除整数会**直接截断小数部分**，`45/180 = 0`。于是 `0 * π = 0`，**旋转角度实际上变成了 0 度**，程序不报错，但就是转不动。

> **铁律：只要涉及除法，先想一下是不是整数除法。**

### 坑 2 ⭐⭐⭐：平移矩阵的对角线必须是 1

```cpp
f << 0,0,1, 0,0,2, 0,0,1;   // ❌ 对角线是 0 → x、y 被乘 0，坐标全丢
f << 1,0,1, 0,1,2, 0,0,1;   // ✅ 对角线全是 1
```

展开看第一个的错误版本：

```
[ 0 0 1 ]   [ x ]   [ 0·x + 0·y + 1 ]   [ 1 ]   ← x 没了
[ 0 0 2 ] · [ y ] = [ 0·x + 0·y + 2 ] = [ 2 ]   ← y 也没了
[ 0 0 1 ]   [ 1 ]   [ 0·x + 0·y + 1 ]   [ 1 ]
```

**平移是"搬运"，不是"重塑"**。对角线上的 `1` 表示"**原样通过、不缩放**"，把它们写成 `0` 就等于把坐标乘 0。

### 坑 3 ⭐⭐⭐：编译器通过 ≠ 逻辑正确

| 错误 | 编译器能抓到吗 |
|---|---|
| `Eigen::Maxtrix3f`（拼写错） | ✅ 会报 `not a member of 'Eigen'`，还附上 `suggested alternative: 'Matrix3f'` |
| `y` 未定义 | ✅ 会报 `was not declared in this scope` |
| 平移矩阵对角线写成 `0` | ❌ **完全不报错，语法类型全对，但结果是错的** |
| `45 / 180` 整数除法 | ❌ **不报错**，静悄悄地算成 0 |

> **编译器只能抓语法，抓不了数学。** 所以必须**手算验证**：
> ```
> 旋转后：x' = 2·cos45 − 1·sin45 = 0.7071
>        y' = 2·sin45 + 1·cos45 = 2.1213
> 平移后：(0.7071 + 1, 2.1213 + 2) = (1.7071, 4.1213)
> ```

### 坑 4：角度 / 弧度

`std::sin`、`std::cos`、`std::tan` 收的都是**弧度**。
`45° = 45/180 × π`。忘了转换就会算出完全离谱的结果。

### 坑 5：Eigen 的 `<<` 是**按行**填充

```cpp
m << 1, 2, 3,
     4, 5, 6,
     7, 8, 9;
```
一行一行往下写，别和"列主序存储"搞混。

### 坑 6：类型不匹配 —— `2.0` 还是 `2.0f`

`Eigen::Matrix3f` 的标量类型是 `float`，写 `i * 2.0` 传的是 `double`。虽然 Eigen 常能隐式转换过去，但**规范写法是 `2.0f`**。

### 坑 7：矩阵乘法不满足交换律

`i * j ≠ j * i`。变换的顺序同理：`T * R * p` 和 `R * T * p` 结果完全不同（见 4.4 节）。

### 坑 8：在共享文件夹里编译会卡死虚拟机

见 2.4 节。**共享文件夹只用来传文件，编译必须在虚拟机本地磁盘。**

### 坑 9：不要手改 `.vbox` 配置文件

VirtualBox 会把内存里的配置**重新写回文件**，你手改的内容会被**静默覆盖**。要用 `VBoxManage` 命令或图形界面修改。

## 七、小结

作业0 表面上只是"一个点做个变换"，但它把三个关键概念一次性串起来了：

1. **齐次坐标为什么存在**——为了让平移也能写成矩阵乘法，从而让所有变换可以**统一合并成一个矩阵**。
2. **变换顺序的本质**——最右边的矩阵最先作用；写在左边的变换会影响右边的位移。
3. **调试的基本功**——编译器只查语法，**数学正确性只能靠手算对照**。

这三条会在之后的每一个作业里反复出现：作业1 的 MVP 矩阵、作业2 的 z-buffer、作业3 的着色，全都建立在这套矩阵运算之上。

> 下一步就是《[作业1：光栅化](/posts/graphics-rendering-pipeline/)》——给三角形填上模型矩阵和透视投影矩阵，把它真正画到屏幕上。
