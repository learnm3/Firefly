## 二、第 2 课：图形学为什么离不开线性代数

图形学的所有计算，归根结底是两件事：**一个点在哪**、**把它搬到哪去**。前者是向量，后者是矩阵乘法。

### 2.1 点积：判断"方向合不合得来"

```
a · b = |a| · |b| · cosθ
```

- 坐标形式：`a·b = xa·xb + ya·yb + za·zb`（对应分量相乘再相加）
- **用途 1：求夹角** —— 光照计算里，光源方向和法线的夹角就是这么算的（Lambert 漫反射）
- **用途 2：求投影** —— `b` 在 `a` 方向上的投影长度是 `k = |b|·cosθ = a·b/|a|`
- **用途 3：判断前后** —— `a·b > 0` 同向，`< 0` 反向，`= 0` 垂直

> 记住：点积的符号直接告诉你两个方向是"一伙的"还是"对着干的"。

### 2.2 叉积：判断"左右和内外"

```
|a × b| = |a| · |b| · sinφ   方向由右手定则决定
```

- **反交换律**：`a × b = −(b × a)`，顺序一换方向就反过来
- **用途 1：判断左右** —— 叉积结果朝里朝外，告诉你 b 在 a 的哪一侧
- **用途 2：判断点在三角形内/外** —— 对三条边依次做叉积，三个结果同号就在内部。后面光栅化逐像素判定"这个像素落在哪个三角形里"，用的就是它

### 2.3 矩阵：变换的流水线

- 矩阵乘法 `(M×N)(N×P) = (M×P)`，结果第 (i,j) 个元素 = A 第 i 行与 B 第 j 列的点积
- **不可交换**：`AB ≠ BA`（先缩放后旋转 ≠ 先旋转后缩放）
- **结合律**：`(AB)C = A(BC)` —— 多个变换可以先乘成一个矩阵，性能关键
- **逆矩阵**：`A⁻¹A = I`，几何上就是"撤销这个变换"；`(AB)⁻¹ = B⁻¹A⁻¹`

> 两个把向量运算和矩阵统一的结论，是下节课的桥：
> 点积 `a·b = aᵀb`；叉积 `a×b = A*·b`（A* 是由 a 分量构成的反对称矩阵）。

## 三、第 3 课：用矩阵统一所有变换

### 3.1 2D 线性变换（都保持原点不动）

| 变换 | 矩阵 `[a b; c d]` | 效果 |
|---|---|---|
| 缩放 | `[s 0; 0 s]` | 均匀放大/缩小 |
| 反射 | `[−1 0; 0 1]` | 沿 y 轴翻转 |
| 剪切 | `[1 a; 0 1]` | y=1 处水平位移 a，正方形推成平行四边形 |
| 旋转（逆时针 θ） | `[cosθ −sinθ; sinθ cosθ]` | 绕原点转 |

### 3.2 齐次坐标：为什么平移不能用 2×2？

平移 `x' = x + tx` 把原点也搬走了，**不是线性变换**，所以 2×2 矩阵写不出来。

解法：给坐标加第三维 `w`：

- **点** = `(x, y, 1)`（w=1，平移对它有效）
- **向量** = `(x, y, 0)`（w=0，平移对它无效——向量本来就没有位置）

```
[x']   [1 0 tx] [x]
[y'] = [0 1 ty] [y]
[1 ]   [0 0 1 ] [1]
```

3D 同理：点 `(x,y,z,1)`、向量 `(x,y,z,0)`，用 4×4 矩阵统一所有仿射变换。

> **面试必答**：齐次坐标的价值 = 把旋转/缩放/平移统一成 4×4 矩阵乘法，并且支持矩阵级联。这正是为什么 GLSL 里顶点都是 `vec4`。

### 3.3 组合变换：顺序不能乱

```
先平移后旋转： R · T(1,0)
先旋转后平移： T(1,0) · R
```

这两个结果完全不同。矩阵**从右往左作用于点**：最右边的变换最先执行。

**绕任意点 c 旋转的三步法**（极高频考点）：

```
T(c) · R(α) · T(−c)
```

先把中心点移到原点 → 旋转 → 再移回去。这个"移到原点处理完再移回来"的套路，第 4 课的视图变换还会用一次。

### 3.4 3D 旋转矩阵（注意 Ry 的符号）

```
Rx(α) = [1 0 0;        Ry(α) = [cosα 0 sinα;      Rz(α) = [cosα −sinα 0;
        0 cosα −sinα;            0 1 0;                  sinα cosα 0;
        0 sinα  cosα]           −sinα 0 cosα]           0    0    1]
```

> **易错点**：`Ry` 里 `sinα` 的符号和 `Rx`、`Rz` 相反，这是坐标轴朝向决定的，写代码时最容易错。

## 四、第 4 课：观测变换——把相机摆好

拍照三步：①摆好模型（Model）→ ②选好相机角度（View）→ ③按快门成像（Projection）。

### 4.1 视图变换（View）

关键观察：**相机和所有物体一起移动，照片不变**。所以约定俗成把相机挪到一个标准位置：

- 相机位置 `e` 平移到原点
- 看向方向 `g` 对齐到 `-Z`
- 上方方向 `t` 对齐到 `+Y`

```
Mview = Rview · Tview
```

- 平移 `Tview`：把 `(xe, ye, ze)` 搬到原点，即平移 `(−xe, −ye, −ze)`
- 旋转 `Rview`：直接写很难，改个思路——先写它的**逆旋转**（把 X→g×t、Y→t、Z→−g），再**转置**。因为旋转矩阵是正交矩阵，逆 = 转置

### 4.2 投影变换：两种投影

| 投影 | 特点 | 用途 |
|---|---|---|
| 正交投影 | 投影线平行，远近一样大 | 工程制图、医学影像 |
| 透视投影 | 投影线汇聚一点，近大远小 | 人眼视觉、游戏画面（最常用） |

### 4.3 正交投影（简单）

把视景体 `[l,r]×[b,t]×[f,n]` 先平移到中心，再缩放到规范立方体 `[−1,1]³`：

```
Mortho = S(2/(r−l), 2/(t−b), 2/(n−f)) · T(−(r+l)/2, −(t+b)/2, −(n+f)/2)
```

> **反直觉点**：相机沿 −Z 看，所以近平面 `n` 的 z 值**大于**远平面 `f`（n > f）。OpenGL 用左手坐标系就是这个原因。

### 4.4 透视投影：把视锥体挤成长方体

两步走：① 把视锥体（frustum）挤成长方体 `Mpersp→ortho`；② 套正交投影。

```
Mpersp = Mortho · Mpersp→ortho
```

#### 第一步：相似三角形推出 x′、y′

点 `(x, y, z)` 投影到近平面 `z=n`，由相似三角形：

```
x' = (n/z)·x
y' = (n/z)·y
```

注意 `z` 在分母——这是个**除法**，不是线性变换。怎么把它变成矩阵乘法？齐次坐标的技巧：整体乘 `z`，把除法藏到归一化里。

```
(x, y, z, 1)   ──乘 z──▶   (n·x, n·y, ???, z)
                              ↑                ↑
                          已知 nx, ny      W=z，归一化后 x'=nx/z
```

---

### ★ 重点一：为什么 z′ 是 unknown？

这是新手最卡的地方。答案：**相似三角形只决定投影位置，不规定挤压后的深度。**

拆开看：

1. 4×4 矩阵作用后得到的是齐次坐标 `(X, Y, Z, W)`，**再除以 W** 才是最终点。
2. 我们已经知道 `X = nx`、`Y = ny`、`W = z`（这样归一化后 `X/W = nx/z` 正好是相似三角形的结果）。
3. 但 `Z`（也就是真正的新深度 `Z/W`）——**投影几何根本没规定它**。

为什么？因为投影是把 3D 压成 2D，**压的过程深度信息是故意丢掉的**：同一根光线上的所有点 `(kx, ky, kz)`，投影后都落到同一个像素上（代入公式 `x' = n/z·x`，k 被约掉了）。底片是一张没有厚度的纸，上面不存在"深度"这根轴，你不可能从底片上读出一个不存在的量。

> 一句话：**相似三角形管"点落在底片哪个像素"，不管"这个点现实里多深"。**

那 z′ 怎么补？它不是算出来的，是我们按两个边界条件**规定**的：

- 挤压时近平面上的点深度不变：`z = n → z' = n`
- 挤压时远平面上的点深度不变：`z = f → z' = f`

设第三行为 `(0, 0, A, B)`，即 `Z = A·z + B`。代入两个边界：

```
An + B = n²
Af + B = f²
```

解出 `A = n + f`，`B = −nf`。这就是最终矩阵：

```
Mpersp→ortho = [n   0    0     0  ]
               [0   n    0     0  ]
               [0   0   n+f  −nf ]
               [0   0    1     0  ]
```

---

### ★ 重点二：挤压后中点去哪了？（近密远疏）

代入中点 `z = (n+f)/2` 看看它被挤到哪：

```
z' = [(n+f)·z − nf] / z
   = (n² + f²) / (n+f)
```

用 OpenGL 常用的 `n=−1, f=−3` 算具体数：

```
原中点 z = (−1 + −3)/2 = −2
挤压后 z' = (1 + 9) / (−4) = −2.5
```

**原来在 −2 的点，被挤到了 −2.5，向远平面方向跑了 0.5。**

把整条曲线画出来（横轴原 z，纵轴挤压后 z′）：

```
z' ↑
   │        ● (n=−1 → −1)
   │       ╱
   │      ╱      实际挤压曲线（向下弯）
   │     ╱
   │    ●  ← 原中点 z=−2，映射到 z'=−2.5（被推远）
   │   ╱
   │  ╱
   │ ● (f=−3 → −3)
   └─────────────────────→ z
```

**结论：透视挤压不是线性压缩，而是"近密远疏"**：

- 近平面附近的深度被**拉开**（z=−1 到 −2 之间跨度大）→ 近处精度高
- 远平面附近的深度被**压扁**（z=−2 到 −3 之间挤在一起）→ 远处精度差

这就是 **z-fighting** 在远处特别严重的根本原因：远处一点点真实深度差，映射到深度缓冲里几乎区分不开，两个三角形就会来回抢像素。

## 五、一句话串起三课

```
向量/矩阵（工具） → 4×4 齐次矩阵（统一表示所有变换）
                  → Mview 把相机搬到原点
                  → Mpersp 把视锥体挤成长方体（z 的账按近远两锚点记）
                  → Mortho 压成 [−1,1]³ 规范立方体
                  → 后面光栅化就在这个立方体内进行
```
