## 题一：不同路径（LeetCode 62）— 网格 DP，客户端地图的第一课

### 题目回顾

[LeetCode 62. 不同路径](https://leetcode.cn/problems/unique-paths/) — 难度：中等

**一个机器人位于 `m × n` 网格的左上角，每次只能向右或向下移动一步，要走到右下角，问共有多少条不同的路径。**

```
输入：m = 3, n = 7    输出：28
输入：m = 3, n = 2    输出：3
输入：m = 7, n = 3    输出：28   （7×3 与 3×7 对称，走法数相同）
```

### 游戏场景：格子地图的"路径计数"是关卡设计的基础

> 战棋、俯视角 RPG、棋盘小游戏里，策划经常要回答一类问题："从出生点到目标点，角色**共有多少种合法走法**？"这直接决定关卡的自由度与难度曲线——走法越多，路线越灵活，关卡越简单；走法被地形压缩，关卡就越紧张。

这道题就是最干净的版本（无障碍、只准右/下），它考的是**状态转移思维**：把一个"到达终点有多少种走法"的大问题，拆成"到达终点前最后一格有多少种走法"的小问题——**动态规划的第一直觉**。

### 解法拆解：dp[i][j] = 上方格 + 左方格

**状态定义**：`dp[i][j]` = 到达格子 `(i,j)` 的走法数。

**转移方程**：到 `(i,j)` 只能从上方 `(i-1,j)` 走下来，或从左方 `(i,j-1)` 走过来，所以：

```
dp[i][j] = dp[i-1][j] + dp[i][j-1]
```

**边界条件**：第一行 `(0,j)` 只能一路向右（只有 1 种走法）、第一列 `(i,0)` 只能一路向下（也只有 1 种走法），所以第一行、第一列全为 1。

**类比**：每个格子都问自己一句话——"**我是被谁走到的？**"要么被上面的人走下来，要么被左边的人走过来，把这两拨走法数加起来就是我的走法数。从 `(0,0)` 出发，一层层往下问，答案自然堆到终点。

```cpp
class Solution {
public:
    int uniquePaths(int m, int n) {
        vector<int> dp(n, 1);              // 一维滚动数组，先表示"第一行"（全 1）
        for (int i = 1; i < m; ++i)        // 从第二行开始逐行填
            for (int j = 1; j < n; ++j)
                dp[j] += dp[j - 1];        // dp[j] = 上方（旧 dp[j]）+ 左方（新 dp[j-1]）
        return dp[n - 1];                  // 最后一格 = 答案
    }
};
```

**复杂度**：时间 O(mn)、空间 O(n)（滚动数组，从 O(mn) 压到 O(n)）。

**终点 6 的含义**：从左上到右下共有 6 条合法路径。可以用组合数交叉验证：一共要走 `m+n-2 = 4` 步，其中向下 `m-1 = 2` 步（其余向右），所以走法 = `C(4, 2) = 6`——**DP 结果与数学公式殊途同归**（这也是面试官常问的"你还能怎么算"）。

### 推导：怎么想到"dp[i][j] = 上 + 左"的

1. **先问终点的递推关系**：到 `(2,2)` 只有两条路进来——从 `(1,2)` 下来、从 `(2,1)` 过来。所以"到终点的走法数" = "到 (1,2) 的走法数" + "到 (2,1) 的走法数"。**大问题被拆成两个更小的同构问题**。
2. **一路往下拆**，任何内部格都有这个性质；只有第一行/第一列没法再拆（它们只有一条直路），于是**边界 = 1** 成为递推的"地基"。
3. **自底向上**（从边界往终点）填表，每个格子只依赖"上方"和"左方"——所以**按行从左到右填**，顺序天然成立。
4. **空间优化**：填第 i 行时只用到第 i-1 行，于是只保留一行数组，`dp[j] += dp[j-1]` 原地滚动（详见上图右侧推导）。

### 坑位专题：dp[-1] 越界 → UBSan 报错全解（实战实录）

如果你把内层循环写成 `j` 从 0 开始：

```cpp
for (int j = 0; j < n; ++j)   // ❌ 错！
    dp[j] += dp[j - 1];       // j=0 时 → dp[0] += dp[-1]
```

力扣会报一段"看起来很高深"的错：

```
Line 1122: Char 34: runtime error: addition of unsigned offset to 0x503000000040 overflowed to 0x50300000003c (stl_vector.h)
SUMMARY: UndefinedBehaviorSanitizer: undefined-behavior .../bits/stl_vector.h:1131:34
```

**逐行解读**：
- `stl_vector.h` 是 `std::vector` 的源码，报错发生在 `operator[]`（下标访问）里
- 地址 `0x...040 → 0x...3c`：**往回跳了 4 个字节**（一个 int 的大小）——指针跑到了数组分配内存的**前面**
- "unsigned offset"：下标是 `size_t`（无符号），-1 被当成巨大的无符号数（2⁶⁴−1），一加就回绕，等价于 `dp[-1]`

**一句话**：你访问了 `dp[-1]`——vector 的负下标越界。力扣默认开 UBSan（UndefinedBehaviorSanitizer），越界会直接拦截报错（而不是静默算错），反而是好事，帮你早发现。

下面这张图把 dp 数组被三行轮流覆盖的过程一次画清（同一块内存，旧的被新的顶掉），配合理解"为什么 dp[j] 旧值 = 上方、dp[j-1] 新值 = 左方"：

![一维滚动数组 dp 的三步演进（uniquePaths(3,4)）](/assets/images/posts/leetcode-daily-02/dp-rolling.svg)

**修复**：`j` 从 1 开始（第 0 列路径数恒为 1，本来就不用更新）：

```cpp
for (int j = 1; j < n; ++j)   // ✅ 唯一改动
    dp[j] += dp[j - 1];
```

**通用排查清单**（其他数组题也适用）：

| 越界写法 | 后果 |
|---|---|
| `dp[j-1]` 而 j 从 0 开始 | `dp[-1]`（本次，地址回绕到分配区之前） |
| `dp[j+1]` 而 j 循环到 n-1 | `dp[n]`（越界，跑到分配区之后） |
| `n=0` 时访问 `dp[0]` | 空数组访问，同样 UBSan 崩 |

**记忆口诀**：凡是有 `dp[j-1]` / `dp[i-1]`（取"前一个"）的循环，下界必须是 1；有 `dp[j+1]` / `dp[i+1]`（取"后一个"）的，上界必须减 1——这是数组类 DP 题最经典的越界坑。

### 面试必答要点

1. **边界为什么全是 1**：第一行只能一路向右、第一列只能一路向下，各只有唯一走法
2. **为什么能压到 O(n)**：每行只依赖上一行 → 一维滚动数组（这是 DP 空间优化的标准话术）
3. **数学解**：走法数 = `C(m+n-2, m-1)`（在总步数里选向下步数的组合数），可作第二解法展示思维广度
4. **小陷阱**：`m=1` 或 `n=1` 时只有一条直线路径，答案恒为 1（代码天然成立）

### 变体延伸

| 变体 | 题号 | 变化 | 解法要点 |
|---|---|---|---|
| 有障碍物的路径 | 63 不同路径 II | 网格里出现障碍格 | 障碍格 `dp=0`；起点/终点是障碍时直接返回 0 |
| 最小路径和 | 64 最小路径和 | 每格有权值，问路径权值总和最小 | 把"计数 +"换成"取小 min"：`dp[i][j] = min(上, 左) + grid[i][j]` |
| 最大正方形 | 221 最大正方形 | 找全 1 的最大正方形面积 | `dp[i][j] = min(上, 左, 左上) + 1`，三方向取小 |

## 题二：长度最小的子数组（LeetCode 209）— 滑动窗口，数据流的"最短达标段"

### 题目回顾

[LeetCode 209. 长度最小的子数组](https://leetcode.cn/problems/minimum-size-subarray-sum/) — 难度：中等

**给定一个正整数数组和一个目标值 `target`，找出和 ≥ target 的长度最小的连续子数组，返回其长度；不存在则返回 0。**

```
输入：target = 7, nums = [2,3,1,2,4,3]    输出：2   （子数组 [4,3]）
输入：target = 4, nums = [1,4,4]          输出：1   （单个 4 就够）
输入：target = 11, nums = [1,1,1,1,1,1,1,1] 输出：0  （全加起来也不够）
```

### 游戏场景：资源加载缓冲与"最短达标段"

> 客户端/TA 日常会碰到一类问题：**显存预算有限，从加载队列里连续取一批资源，总量要达到阈值，最少取几个？**——这就是"和 ≥ target 的最短连续段"。也像**技能连招输入窗口**（连续输入必须落在指定步数内）、UI 数据流处理窗口。关键词是"**连续**"+"**最短**"，这类题的标准武器就是**滑动窗口**。

### 解法拆解：右指针扩张、左指针收缩，O(n)

**核心思路**：维护 `[left, right]` 一段连续区间（窗口）：
1. **右指针扩张**：`right` 一直向右走，每走一步把 `nums[right]` 加进窗口和
2. **左指针收缩**：一旦窗口和 ≥ target，就尝试把左端元素扔掉（`left` 右移），一边扔一边更新"最短长度"——直到和重新 < target 为止
3. 全程记录 `min(答案, right-left+1)`，扫完整个数组得到最短长度

```cpp
class Solution {
public:
    int minSubArrayLen(int target, vector<int>& nums) {
        int n = nums.size();
        int left = 0, sum = 0, ans = INT_MAX;
        for (int right = 0; right < n; ++right) {
            sum += nums[right];                  // 右指针：扩张窗口
            while (sum >= target) {              // 窗口满足条件
                ans = min(ans, right - left + 1); // 记录当前长度
                sum -= nums[left++];             // 左指针：收缩找更短
            }
        }
        return ans == INT_MAX ? 0 : ans;         // 全程没达标 → 0
    }
};
```

**复杂度**：时间 O(n)、空间 O(1)。

**类比**：一条传送带——右手往右端不断放货（扩张），一旦够重就记下当前段长度，然后左手把左端货物搬走（收缩）再比。**每件货最多被右手放进一次、左手搬出一次**，所以整体线性。

### 实例逐步演示：指针位置全记录

拿 `nums = [2,3,1,2,4,3]`、`target = 7`，下图完整还原窗口 6 步流转（橙 = 当前窗口，绿 = 最终答案窗口）：

![209 长度最小的子数组：滑动窗口逐步演示](/assets/images/posts/leetcode-daily-02/sliding-window.svg)

用表格再走一遍（每一步的窗口与动作）：

| 步 | 窗口 [left..right] | 窗口和 | 动作 | 记录 |
|---|---|---|---|---|
| 1 | [2]（r=0） | 2 | 和 < 7，右移扩张 | — |
| 2 | [2,3,1]（r=2） | 6 | 仍 < 7，继续右移 | — |
| 3 | [2,3,1,2]（r=3） | 8 | ≥ 7！开始收缩 | len=4 |
| 4 | [3,1,2,4]（r=4） | 10 → 收缩到 7 | 收缩：记 4 → 记 3 → 和 6 停 | len=3 |
| 5 | [2,4,3]（r=5） | 9 → 收缩到 7 | 收缩：记 3 → 记 2 ✓ → 和 3 停 | **len=2** |
| 6 | [4,3] | 7 | 最短窗口，长度 2 | 答案 = 2 |

**答案 2 对应的窗口是 `[4,3]`**——它是和恰好 = 7 且最短的一段。

### 推导：怎么想到"滑动窗口"的

1. **暴力长什么样**：枚举所有起点和终点，O(n²) 地试每个连续段——太慢。
2. **观察单调性**：数组全是**正整数**，所以窗口**右移和变大、左移和变小**——"和"随边界移动是单调的，不需要回溯试探。
3. **关键洞察**：一旦 `left` 因为"和够了"向右挪过，**它永远不需要再往左挪回来**（因为再往左和只会更大，长度只会更长，对"最短"无益）。于是 left、right **两个指针都只向右移动**，全程各走一遍 → O(n)。
4. **这就是滑动窗口的由来**：用两个单向指针维护一段"会滑动的区间"，把 O(n²) 暴力压成 O(n)。

### 面试必答要点

1. **为什么是 O(n)**：right 把每个元素加进窗口一次，left 把每个元素减出窗口一次，无重复扫描
2. **为什么要求数组全为正数**：单调性前提——含负数时"右移变大、左移变小"失效，得改用前缀和 + 二分（O(n log n)）
3. **窗口满足条件后为什么用 while 收缩**：可能扔掉一个还够（如本例连续记 4、3、2），要收缩到"再扔就不够"为止
4. **无解返回 0**：`ans` 保持 `INT_MAX` 没更新过，说明全数组和都不足

### 变体延伸

| 变体 | 题号 | 变化 | 解法要点 |
|---|---|---|---|
| 无重复字符的最长子串 | 3 | 窗口内字符不能重复 | 哈希表记录字符最后出现位置，重复时 left 直接跳到该位置后 |
| 最小覆盖子串 | 76（困难） | 窗口要覆盖 T 的所有字符 | 哈希计数 + 缺字符计数，满足后收缩 |
| 滑动窗口最大值 | 239（困难） | 固定窗口大小，输出每个窗口最大值 | 单调队列（双端队列存下标） |

## 题三：数组中的第 K 个最大元素（LeetCode 215）— Top-K，排行榜的常青题

### 题目回顾

[LeetCode 215. 数组中的第 K 个最大元素](https://leetcode.cn/problems/kth-largest-element-in-an-array/) — 难度：中等

**给定整数数组 `nums` 和整数 `k`，返回数组中第 k 个最大的元素（按从大到小排序后第 k 个）。注意要求的是"第 k 大"，不是第 k 小。**

```
输入：nums = [3,2,1,5,6,4], k = 2    输出：5
输入：nums = [3,2,3,1,2,4,5,5,6], k = 4  输出：4
```

### 游戏场景：排行榜 Top-K 与掉落权重池

> 排行榜只关心**前 10 名**，第 11 名之后谁大谁小无所谓；掉落池要挑**权值最高的 K 个奖励**；性能分析要看**最耗时的 K 个热点函数**。这些场景的共同点是：**只关心前 K 个，不关心完整排序**——排序是 O(n log n)，Top-K 只需要 O(n log k)，数据越大差距越明显。

### 解法拆解：小顶堆永远只留"最大的 k 个"

**核心思路**：维护一个**大小为 k 的小顶堆**：
- 遍历数组，每个元素先 `push` 进堆
- 堆一旦超过 k 个元素，就 `pop` 掉堆顶——**堆顶是堆里最小的**，pop 掉它 = 踢走"候选席里的最后一名"
- 遍历完，堆里剩下的就是"最大的 k 个"，堆顶 = 第 k 大

```cpp
class Solution {
public:
    int findKthLargest(vector<int>& nums, int k) {
        priority_queue<int, vector<int>, greater<int>> pq;  // 小顶堆（greater<int>）
        for (int x : nums) {
            pq.push(x);
            if ((int)pq.size() > k) pq.pop();  // 超员就踢走堆顶（当前最小的）
        }
        return pq.top();                       // 堆顶 = 第 k 大
    }
};
```

**复杂度**：时间 O(n log k)（每个元素一次 O(log k) 的堆操作）、空间 O(k)。

**类比**：公司只留 K 个 VIP 候选席，**堆顶就是候选席的门槛（最弱的一位）**。新人比门槛高 → 挤进来、把门槛挤出去；比门槛低 → 连门都进不了。从头到尾只关心"够不够格进前 K"，后面的无所谓——所以不用排序。

### 零基础语法拆解：小顶堆代码的三个细节

**① `priority_queue<int, vector<int>, greater<int>>` 为什么是小顶堆**

三个模板参数：元素类型 `int` / 底层容器 `vector<int>` / 比较器 `greater<int>`。最容易懵的是第 ③ 个：`greater<int>` 字面意思是"大于"，却让**小的元素排前面**——因为优先队列的规则是 `compare(a,b)` 返回 true 表示 a 优先级更低（排后面），`greater` 让"大的排后面"，于是堆顶永远是最小值 → **小顶堆**。对比：`priority_queue<int>` 默认是 `less<int>` = 大顶堆（堆顶最大）。

**② `for (int x : nums)` 范围 for**

把 `nums` 从头到尾遍历，每次取出一个元素**拷贝**给 `x` 再执行循环体。等价于：

```cpp
for (size_t i = 0; i < nums.size(); ++i) {
    int x = nums[i];
    pq.push(x);
}
```

- `int x`：拷贝，改 x 不影响原数组（只读遍历最常用）
- `int& x`：引用，改 x 就改原数组
- `const auto& x`：只读 + 不拷贝，元素是 string/对象时省内存

**③ `(int)pq.size() > k` 为什么强转**

`pq.size()` 返回 `size_t`（**无符号**），`k` 是 `int`（**有符号**）。两者比较时 `int` 会被隐式转成无符号——若 k 为负，会被当成巨大的无符号数（2⁶⁴−1），比较结果反转（比如 `0 > -1` 会变成 false）。加 `(int)` 让两边同为 int，**消除编译器警告 + 防御非法输入**。本题 k≥1 不加也能过，但这是刷题好习惯。

### 实例逐步演示：k = 2 的堆流转全程

拿 `nums = [3,2,1,5,6,4]`、`k = 2`，下图把 6 步遍历的堆状态画全（堆顶 = 门槛）：

![215 数组中的第 K 个最大元素：小顶堆流转](/assets/images/posts/leetcode-daily-02/topk-heap.svg)

表格再走一遍：

| 步 | 当前元素 | 操作 | 堆内（≤2 个） | 堆顶 |
|---|---|---|---|---|
| ① | 3 | push | [3] | 3 |
| ② | 2 | push | [2,3] | 2 |
| ③ | 1 | push 后超员 → pop 1 | [2,3] | 2 |
| ④ | 5 | push 后超员 → pop 2 | [3,5] | 3 |
| ⑤ | 6 | push 后超员 → pop 3 | [5,6] | 5 |
| ⑥ | 4 | push 后超员 → pop 4 | [5,6] | **5 = 答案** |

**关键观察**：元素 1 和 4 虽然进过堆，但因为比"当前前二名"弱，马上被踢了出去；**5 始终稳在前二**，最终堆顶 5 就是第 2 大。

### 推导：怎么想到"小顶堆 + 只留 k 个"的

1. **先拒绝排序**：完整排序得到前 k 个是 O(n log n)，但"第 k 大"只关心**名次边界**，不需要全序。
2. **换一个问法**："第 k 大" = "**前 k 名里的最后一名**"。这个身份的本质是"门槛"——只要我能随时知道**当前第 k 名是谁**，再来新人就能立刻判断：比我强就顶替我，比我弱就忽略。
3. **什么数据结构擅长维护"极值"**：堆。但这里要维护的是"**前 k 名中的最小者**"（门槛），所以用**小顶堆**——堆顶 = 最小 = 门槛；新人比堆顶大就替换。
4. **为什么不是大顶堆**：大顶堆的堆顶是最大者，无法体现"门槛"语义；大顶堆适合"合并前 k 个最小"之类对称问题（求第 k 小）。
5. **控制堆大小 = 控制成本**：堆永远只有 k 个元素，每步操作 O(log k) → 总 O(n log k)。k 远小于 n 时，比排序快一个量级。

> **另一解法：快速选择（Quick Select）**——借用快排的 partition 把数组分成"大/小"两半，若大的那半边正好 k 个则答案就在边界，平均 O(n)、最坏 O(n²)。面试答堆是最稳的；提到快选可以展示对快排的理解。

### 面试必答要点

1. **为什么第 k 大用小顶堆**：堆顶 = "前 k 名的门槛（最小者）"，新元素与堆顶比较即可决定去留
2. **push 后 pop 的时机**：先 push 再判 size > k → pop，保证堆内恒为 k 个
3. **复杂度口径**：O(n log k)，不是 O(n log n)；空间 O(k)
4. **流式场景的升级**：数据是源源不断的流（榜单实时刷新）时，堆解法天然在线——这就是 703 题的背景
5. **对照**：`priority_queue<int>` 默认是大顶堆；`greater<int>` 让它变成小顶堆（这行代码面试经常被追问）
