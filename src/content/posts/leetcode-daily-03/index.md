## 题一：二叉树的层序遍历（LeetCode 102）— BFS，场景树的第一课

### 题目回顾

[LeetCode 102. 二叉树的层序遍历](https://leetcode.cn/problems/binary-tree-level-order-traversal/) — 难度：中等

**给你二叉树的根节点，返回其节点值的层序遍历（逐层从左到右访问，每层一个数组）。**

```
输入：root = [3,9,20,null,null,15,7]（层序数组表示）
输出：[[3],[9,20],[15,7]]
输入：root = []    输出：[]
输入：root = [1]   输出：[[1]]
```

### 游戏场景：UI 层级树与场景树都要"一层一层处理"

> 客户端的 UI 面板是**层级树**：绘制时父面板先画、子面板再画（深度排序）；场景管理器要**按深度**遍历 GameObject 树（先处理一层对象，再处理它们的子对象）；渲染排序也常把同层对象分组处理。"按层遍历一棵树"是客户端引擎的基础操作，BFS 就是它的标准武器。

### 解法拆解：BFS + 队列，sz 快照是关键

**核心思路**：用队列做**广度优先搜索（BFS）**。从根开始，把每层节点按"先进先出"处理，处理完一层再进下一层。

真正的关键技巧只有一行：**每轮开始前先拍快照 `sz = q.size()`，然后只循环 sz 次**。

```cpp
class Solution {
public:
    vector<vector<int>> levelOrder(TreeNode* root) {
        vector<vector<int>> ans;
        if (!root) return ans;
        queue<TreeNode*> q;
        q.push(root);
        while (!q.empty()) {
            int sz = q.size();               // ★ 先拍快照：本层节点数
            vector<int> level;
            for (int i = 0; i < sz; ++i) {   // ★ 只处理"本层"这 sz 个
                TreeNode* cur = q.front(); q.pop();
                level.push_back(cur->val);
                if (cur->left)  q.push(cur->left);   // 孩子入队 = 预排进下一层
                if (cur->right) q.push(cur->right);
            }
            ans.push_back(level);            // 本层收工，进入下一轮
        }
        return ans;
    }
};
```

**复杂度**：时间 O(n)（每个节点恰好入队出队一次）、空间 O(n)（队列最多容纳一层节点数，最坏 O(n)）。

**类比**：影院按"批"叫号——每批开始先数清这一批几个人（`sz`），把这批全部接待完（弹完），他们带来的孩子（左/右子树）排到下一批。**先拍快照再放人，批次就不会混**。

### 坑位专题：为什么必须 `sz = q.size()` 提前存

如果直接写成：

```cpp
for (int i = 0; i < q.size(); ++i)   // ❌ 错！q.size() 是动态的
```

就错了：循环体里 `q.pop()` 会让 `q.size()` 变小，`q.push()` 又会让它变大——**q.size() 在循环过程中一直在变**，循环次数完全不可控，会把下一层节点也卷进本层数组。

提前 `sz = q.size()` 相当于把"这一批的人数"定格在进场前：后面的入队出队怎么变，都不影响本批的处理量。这就是层序遍历唯一最容易写错、也最值得在面试时说清楚的点。

用表格再走一遍（重点看 sz 如何切层）：

| 轮 | 进入循环时队列 | sz | 处理 | 层结果 |
|---|---|---|---|---|
| 1 | [3] | 1 | 弹 3 → 入 9、20 | [3] |

### 推导：怎么想到"BFS + sz 快照"的

1. **先想"按层"是什么意思**：同一层的节点，从根出发的**步数相同**。因此"先访问完所有一步可达的，再访问两步可达的"——这正是 BFS 的定义（一层一层向外扩散）。
2. **队列为什么天然适合 BFS**：先进先出，先入队的先处理，恰好就是"先来先接待"的层级顺序。DFS（递归/栈）是"一条路走到黑"，做不到"逐层成组输出"。
3. **怎么让"一层"成为一个数组**：直接 `while (!q.empty())` 会把所有节点塞进一个大数组，分不出层。于是想到"**每轮只处理当前这批**"——用 `sz` 定格本批数量，`for` 循环恰好弹掉这一批，剩下的就是下一批。
4. **这就是 sz 快照的由来**：队列是动态的，只有提前把"本批人数"存下来，`for` 循环才能精确弹完一层。

### 面试必答要点

1. **为什么用队列**：BFS 的层级顺序 = 队列先进先出；DFS 无法自然按层分组
2. **为什么先存 sz**：队列在循环中边弹边入队，`q.size()` 是动态的；不拍快照会把下层节点混进本层
3. **复杂度口径**：每个节点入队出队各一次 → O(n)；空间 = 队列最大长度 ≤ 一层节点数
4. **BFS 与 DFS 的选择**：要"按层/最短路径"用 BFS；要"全路径枚举/回溯"用 DFS
5. **进阶追问**：改成自底向上输出？——答案 `reverse(ans.begin(), ans.end())` 即可（107 题）

## 题二：反转链表（LeetCode 206）— 三指针，客户端手写题之王

### 题目回顾

[LeetCode 206. 反转链表](https://leetcode.cn/problems/reverse-linked-list/) — 难度：简单

**给你单链表的头节点 head，反转链表，并返回反转后的头节点。**

```
输入：head = [1,2,3,4,5]    输出：[5,4,3,2,1]
输入：head = []            输出：[]
输入：head = [1]           输出：[1]
```

### 游戏场景：对象池回收与存档顺序翻转

> 客户端的**对象池**回收链表常按"最近最常使用"排序，倒序处理时要把链表掉个头；**存档/序列化**要把记录顺序翻转；**撤销栈**（后进先出）的数据落盘时也要逆序。更实际的是：这是**客户端/TA 面试出现频率最高的一道手写链表题**，能完整写对三指针逻辑本身就是加分项。

### 解法拆解：prev / cur / nxt 三指针，先存再掉头

**核心思路**：从头到尾走一遍，每到一个节点就把它**掉头**——`next` 改为指向前一个节点。全程只动链表自己的指针，**不新建任何节点**（O(1) 空间）。

```cpp
class Solution {
public:
    ListNode* reverseList(ListNode* head) {
        ListNode* prev = nullptr;   // 前一个（一开始没有）
        ListNode* cur = head;       // 当前要处理的节点
        while (cur) {
            ListNode* nxt = cur->next;   // ① 先记住后一个（防断链）
            cur->next = prev;            // ② 当前节点掉头
            prev = cur;                  // ③ prev 前进
            cur = nxt;                   // ④ cur 前进
        }
        return prev;                     // 循环结束，prev = 原链表尾 = 新链表头
    }
};
```

**复杂度**：时间 O(n)（每个节点处理一次）、空间 O(1)（原地，只有三个指针）。

**类比**：一串人挨个"向后转"——转身前先记住身后是谁（`nxt`），转身指向标记官（`prev`），标记官站到自己位置，自己再走向下一位。**口诀：先存后指，三针齐步**。

### 实例逐步演示：1→2→3→4→5 六帧全程

下图把初始状态、4 次处理、最终结果的完整指针位置画全（橙 = 已反转部分，灰 = 未处理部分）：

![206 反转链表：三指针逐步演示](/assets/images/posts/leetcode-daily-03/reverse-linked-list.svg)

用表格再看指针每一步的归属：

| 步骤 | 操作 | prev | cur | nxt | 链表状态（未处理部分） |
|---|---|---|---|---|---|
| 初始 | — | ⊥ | 1 | 2 | 1→2→3→4→5 |
| 第 1 步 | 1 掉头指 ⊥ | 1 | 2 | 3 | 2→3→4→5（反转部分：1→⊥） |
| 第 2 步 | 2 掉头指 1 | 2 | 3 | 4 | 3→4→5（反转部分：2→1→⊥） |
| 第 3 步 | 3 掉头指 2 | 3 | 4 | 5 | 4→5（反转部分：3→2→1→⊥） |
| 第 4 步 | 4 掉头指 3 | 4 | 5 | ⊥ | 5（反转部分：4→3→2→1→⊥） |
| 第 5 步 | 5 掉头指 4 | 5 | ⊥ | — | （全部反转：5→4→3→2→1→⊥） |

**关键观察**：`cur` 走到的每个节点都先记下后继（`nxt`），再掉头——如果顺序反了（先掉头再记），链表当场断成两截，后面的节点就找不到了。

### 推导：怎么想到"三指针"的

1. **先拒绝新建链表**：空间要求 O(1)，意味着必须**原地**改指针。
2. **掉头的最小代价**：把 `cur->next` 改成指向前一个节点，需要"前一个"在手——所以必须有一个 `prev` 指针跟着走。
3. **掉头的副作用**：`cur->next` 被改写后，**原来的后继就丢了**，循环没法继续——所以必须**先存下 `nxt`**，用完再让 `cur` 跳过去。
4. **三指针的职责**：`prev` 管"已反转部分的头"，`cur` 管"正在掉头的节点"，`nxt` 管"还没轮到的那段"。各自前进，循环 n 次完成。
5. **循环结束后 prev 为什么是答案**：最后一次掉头后 `cur` 变空，`prev` 恰好停在原链表最后一个节点——它就是新链表头。

### 面试必答要点

1. **为什么先存 nxt**：`cur->next` 一旦被改写，原后继就丢了；先存后指是这道题的安全底线
2. **递归写法**（必被追问）：`reverseList(head->next)` 先把后面反转，再让 `head->next->next = head` 掉头；基例 = 空节点或单节点
3. **复杂度**：O(n) 时间、O(1) 空间（递归版空间 O(n) 栈深，面试时可对比）
4. **怎么验证**：遍历一遍新链表看是否逆序；空链表/单节点链表直接返回本身

## 题三：最小栈（LeetCode 155）— 辅助栈，O(1) 极值的工程模板

### 题目回顾

[LeetCode 155. 最小栈](https://leetcode.cn/problems/min-stack/) — 难度：中等

**设计一个支持 push、pop、top 操作，并能在 O(1) 时间内检索到最小元素的栈。**

```
操作序列：push(-2) → push(0) → push(-3) → getMin() → pop() → top() → getMin()
结果：getMin() = -3，top() = 0，getMin() = -2
```

### 游戏场景：资源栈的"峰值追踪"与撤销栈的极值

> 客户端的**资源栈**要随时知道当前占用的最高/最低水位；**编辑器撤销栈**每次入栈一个状态、回退时要立刻知道"当前最极端的状态"；技能系统的**状态栈**（Buff 叠加）也常要 O(1) 查极值。这类"普通栈 + 极值同步"的组合是工程数据结构的经典模板——面试官考察的就是**能不能用辅助结构换取时间**。

### 解法拆解：双栈，minSt 记录"到当前位置为止的最小值"

**核心思路**：一个主栈 `st` 正常干活，另一个辅助栈 `minSt` **平行同步**——它的每个位置都记录"主栈到当前高度为止的最小值"。

```cpp
class MinStack {
    stack<int> st;      // 主栈
    stack<int> minSt;   // 辅助栈：第 i 层 = st 前 i+1 个元素里的最小值
public:
    void push(int val) {
        st.push(val);
        // 新值 ≤ 当前最小值才入；否则最小值没变，复制一份"当前最小"即可
        if (minSt.empty() || val <= minSt.top()) minSt.push(val);
        else minSt.push(minSt.top());   // 等值写法：直接把当前最小再压一层
    }
    void pop() {
        if (st.top() == minSt.top()) minSt.pop();  // 弹出的正是当前最小 → 同步弹
        st.pop();
    }
    int top() { return st.top(); }
    int getMin() { return minSt.top(); }           // 栈顶永远 = 当前最小值
};
```

**复杂度**：push/pop/top/getMin 全部 O(1) 时间；空间 O(n)（最坏 minSt 与 st 等高）。

**类比**：流水账旁边配一本"**最低记录账**"——每来一个数，如果刷新了最低就记一笔新的；没有刷新就照抄上一笔。出栈时如果出掉的正是当前最低记录，就把那笔账划掉。**两本账高度永远一致，最低值永远在顶上**。

### 实例逐步演示：6 步操作双栈状态全记录

下图完整还原 `push(-2) push(0) push(-3) push(5) pop() pop()` 过程中主栈与 minSt 的每一步状态，右上角另附"重复最小值陷阱"图解：

![155 最小栈：双栈逐步演示](/assets/images/posts/leetcode-daily-03/min-stack.svg)

表格再看一遍（minSt 每层 = "到该高度为止的最小值"）：

| 步 | 操作 | 主栈 st（顶→底） | minSt（顶→底） | 说明 |
|---|---|---|---|---|
| ① | push(-2) | -2 | -2 | 空栈直接入 |
| ② | push(0) | 0, -2 | -2, -2 | 0 > -2，最小值没变 → 复制 -2 |
| ③ | push(-3) | -3, 0, -2 | -3, -2, -2 | -3 ≤ -2，新低 → 入 |
| ④ | push(5) | 5, -3, 0, -2 | -3, -3, -2, -2 | 5 > -3，最小值没变 → 复制 -3 |
| ⑤ | pop() | -3, 0, -2 | -3, -2, -2 | 弹出的 5 ≠ minSt 顶 -3 → minSt 不动 |
| ⑥ | pop() | 0, -2 | -2, -2 | 弹出的 -3 == minSt 顶 -3 → 同步弹 |
| ⑦ | getMin() | — | 顶 = **-2** ✓ | O(1) 取最小 |

**关键观察**：`minSt` 的栈顶在任何时刻都等于主栈当前的最小值——这就是"O(1) 查最小"的全部秘密：**把查询要花的 O(n) 时间，提前摊销成 push/pop 时的 O(1) 记账**。

### 坑位专题：push 为什么必须用 `<=`（重复最小值陷阱）

如果写成 `val < minSt.top()`（严格小于），重复最小值时会漏记：

```
push(1) → minSt = [1]
push(1) → 1 < 1 不成立 → 不入 → minSt = [1]   ❌ 漏记
pop()   → 弹出的 1 == minSt 顶 1 → 同步弹 → minSt = []   ❌ minSt 空了！
getMin() → 崩溃 / 未定义行为
```

用 `<=`（或"else 复制当前最小"的等值写法）则：两个 1 都入，pop 一次只弹掉一个，minSt 还剩一个 1，`getMin()` 依然正确。**重复值是最容易让辅助栈逻辑崩掉的场景，也是面试官最爱的追问点**。

### 推导：怎么想到"双栈"的

1. **先想清楚瓶颈**：栈本身只能 O(1) 看栈顶，getMin 要 O(1) 意味着"最小值"这个信息**必须随时在手边**，不能现找。
2. **信息藏在高度里**：栈的最小值随高度变化——push 一个更小的数，最小值更新；pop 掉最小值，最小值回退。所以"最小值"本质是**伴随每个高度的历史信息**。
3. **用一个平行栈记录它**：`minSt` 第 i 层就存"主栈前 i+1 个元素的最小值"。这样任意时刻 `minSt.top()` 就是答案，且 push/pop 时两栈同步移动，全 O(1)。
4. **为什么不是别的结构**：平衡树能查最小但 O(log n)；堆能查最小但无法快速 pop 指定元素（栈的 pop 是任意位置的）；只有平行栈让"极值"与"位置"一一对应，成本最低。

### 面试必答要点

1. **为什么 minSt 能保证 O(1)**：极值信息随高度同步记账，查询 = 直接看顶
2. **push 为什么用 <=**：重复最小值必须都记录，否则连续 pop 两个最小值时 minSt 会提前空掉
3. **pop 为什么要比顶**：只有弹出的是当前最小值时 minSt 才同步弹，否则最小记录不能被误删
4. **空间为什么 O(n)**：最坏情况（单调递减入栈）minSt 与主栈等高
5. **进阶**：`232 用栈实现队列` 是同一思路的姊妹题（两个栈倒置）

## 今日总结：三道题对应岗位面试的三块基本功

| 题 | 核心考点 | 岗位映射 | 面试官想听什么 |
|---|---|---|---|
| 102 层序遍历 | BFS、队列、分层 | **客户端**：UI/场景树层级遍历、渲染队列 | 为什么队列；为什么先存 sz；复杂度 O(n) |
| 206 反转链表 | 链表指针操作 | **客户端**：对象池回收、序列化翻转 | 为什么先存 nxt；递归写法；O(1) 空间 |
| 155 最小栈 | 辅助栈、空间换时间 | **客户端/TA**：资源栈极值、撤销栈 | 为什么双栈；push 用 ≤；pop 比顶 |

**一句话带走**：BFS 先问"**这一批几个人**"（sz 快照防混层），链表反转先问"**断了怎么办**"（先存 nxt 再掉头），极值栈先问"**信息记在哪**"（平行栈随高度记账）——三道题各练一种工程直觉，全部是客户端/TA 面试真正会用的思维。

**复习建议**：明天做题前，先不看代码把这 6 个知识点复述一遍——① 层序 = BFS + 队列，先 sz 快照再循环；② 每个节点入队出队各一次 → O(n)；③ 反转链表 = prev/cur/nxt 三指针，先存后指；④ 反转空间 O(1)，递归版空间 O(n)；⑤ 最小栈 = 主栈 + minSt 平行记账；⑥ push 用 ≤、pop 比顶同步。能讲出来，才算真的带走。
