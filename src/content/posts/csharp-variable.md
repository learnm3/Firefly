这周的 C# 课讲"变量"。刚上课时我觉得这有什么好讲的——无非是给数据起个名字。可当我在 Unity 2023.2.20f1c1 里新建脚本、配上 Visual Studio 2022 亲手敲了几行,又挨了几个编译错误之后,才发觉"变量"背后藏着不少值得琢磨的东西。这篇就当作我上完课、复习过后的理解笔记。

## 变量,我这样理解

讲师给的比喻,我觉得比干巴巴的定义好用:变量就像一个贴了标签的储物格。声明变量,等于先占下一个格子、把标签贴上去,标签就是变量名;赋值,才是把数据真正放进格子里。之后想用这份数据,不用到处抄,喊一声变量名就能读,也能随时往格子里换新内容。玩家的金币数一直在变,与其在代码里写死,不如声明一个 gold,让它在游戏里跟着涨。

数据类型管的是"格子能放什么、能放多大":数据的种类、占的内存大小、取值范围,以及能对它做的操作。char 的格子只放单个字符,bool 只收 true 或 false,硬把小数塞给 int 就会出乱子。讲师还讲到存储方式:值类型把数据直接存在栈内存,像钞票装进钱包;引用类型存的是指向堆内存的"钥匙",像拿钥匙开保险柜取钱。值类型转引用类型叫装箱(把物件装进快递盒),转回来叫拆箱,频繁装箱拆箱会白白增加 CPU 和内存负担,循环里尤其要当心。

## 常用类型与声明赋值

新手最常用的应该是 int、float、string、bool 四个,我拿"玩家数据"把它们串起来写了一遍,在 Unity 里用 Debug.Log 验证:

```csharp
int gold = 100;              // 整数:玩家金币
float hp = 87.5f;            // 浮点数:当前血量,小数记得带 f
string playerName = "小明";  // 字符串:玩家名字
bool isAlive = true;         // 布尔:是否存活

hp = hp - 12.5f;             // 被怪物打掉 12.5 血,往格子里放新值
gold = gold + 50;            // 又捡到 50 金币

Debug.Log(playerName + " 的血量:" + hp);
Debug.Log("剩余金币:" + gold);
Debug.Log("存活状态:" + isAlive);
```

声明可以带着赋值一步完成,也可以先声明后赋值;但用之前一定要先初始化,否则编译器会报错。选什么类型,例子其实已经说明:整数用 int,带小数用 float,文字用 string,只有"是/否"的状态用 bool。讲义里的"怪物信息"我也照着敲了一遍,把名字、等级、血量各存各的再打出来,思路完全一样。

## 命名与规范

变量名就是储物格的标签,起得好不好,直接决定别人——包括一周后的我自己——能不能看懂。命名习惯我没死记,是从讲师给的例子琢磨出来的:类名首字母大写,像 HelloWorld、Example;普通变量小写开头,多词拼一起时后面的单词首字母大写,比如 playerName,这种叫驼峰式;类的成员变量常带下划线前缀,像 _score。名字还要有含义,age 就老老实实叫 age,别用 a1、x2 打发。顺带记住 C# 区分大小写,age 和 Age 是两个变量,前后要统一。

讲师给的取值范围表里,我先把这几个常用的收进小表,方便回看:

| 类型 | 是什么 | 范围 / 特点 |
|---|---|---|
| int | 32 位有符号整数 | -2147483648 ~ 2147483647(约 ±21 亿) |
| float | 32 位浮点数,约 7~8 位有效数字 | ±1.5×10^-45 ~ ±3.4×10^38 |
| double | 64 位浮点数,15~17 位有效数字 | 更大、更精确的小数 |
| char | 16 位 Unicode 字符(2 字节) | 单个字符 |
| bool | 1 字节布尔值 | true 或 false |
| string | 引用类型的文本 | 长度不定 |

## 容易踩的坑

把这一路的报错攒一攒,基本就下面几条,都是我拿讲义例子亲手验证过的:

1. 未初始化就使用:声明完不赋值直接拿来读,编译器直接报错;要么声明时初始化,要么先赋值再用。
2. float 忘了写 f:小数字面量默认按 double 处理,我写 `float hp = 100.0;` 直接类型不匹配报错,补成 `100.0f` 才过。
3. 类型不匹配硬塞:高精度转低精度不会自动转,double 不能直接赋给 int;就算强转,`(int)3.14` 也只得到 3,小数被截断。讲义作业里 `short s2 = us1;` 不合法,也是因为 ushort 的范围放不进 short。
4. 越出作用域就看不见:在花括号块内声明的局部变量只在块内有效,像卧室的灯,出门就灭。最内层块里声明的 c,到外层想 Debug.Log 它,直接编译错误。
5. 字符串转数字不先检查:字符串内容不是有效数字时,int.Parse("abc") 会抛异常;拿不准就换 TryParse,它返回 bool 告诉我成没成功,安全得多。

## 小结与我的思考

复习完,"变量"在我脑子里终于不只是一个名词:它是贴了标签的储物格,声明是占位,赋值是放东西,类型决定格子的规格,命名决定标签好不好认;顺着它又牵出装箱拆箱、类型转换、作用域一串内容,每一个都能展开成坑。想得多了,我反倒觉得类型选择特别"游戏":怪物血量用 float 因为可能掉小数,金币用 int,存活与否用 bool——数据天生是什么样子,就该选什么格子装。上课时"听懂"很轻松,自己敲一遍才发现理解和会用之间差着好多次报错,这大概就是为什么讲师总让我们动手多练吧。
