## 本集要解决的问题

前面几集我们把绘制调试形状（球、线、点、向量）封装成了**宏**，但它们目前定义在 `Slash.h` —— 这个项目级别的**总头文件**里。

问题在于：`Slash.h` 会被各个类到处 include，一旦把宏、声明等杂七杂八的东西都堆进去，**每个 include 它的文件都会拿到一切**。更好的做法是模块化：让"调试宏"住进**自己专属的头文件**，谁需要调试能力，谁才去 include 它。

---

## 一、在 Visual Studio 中新建自定义头文件

1. 在解决方案资源管理器里右键项目 → **添加 → 新项**；
2. 选择 **头文件（.h）**，命名为 `DebugMacros.h`；
3. 点击添加，得到一个新的空头文件。

### 关键坑：文件默认会被放到 Intermediate

VS 默认会把新头文件放进 **Intermediate（中间）目录**——它是**自动生成**的，每次编译都会被反复覆盖清空。也就是说：如果不改位置，**第一次真正编译后这个文件就消失了**。

所以必须把它放到一个持久、不会被清理的位置：项目 **Source 文件夹**内（与 `Private` / `Public` 文件夹同级）。

> 操作：点击「浏览」向上跳几级，直到看到项目的 `Source` 文件夹，双击进入，把文件放在 `Private`、`Public` 旁边，点「选择文件夹」再「添加」。

---

## 二、把宏搬进 DebugMacros.h

1. 回到原来定义宏的位置（`Slash.h`），`Ctrl + X` **剪切**这些调试宏；
2. 打开新的 `DebugMacros.h`，`Ctrl + V` 粘贴进去；
3. 调试宏背后调用的是绘制调试形状的函数（如 `UKismetSystemLibrary` 的 `DrawDebug*`），通常需要 `#include "DrawDebugHelpers.h"`。把这条 include 也从 `.cpp` 挪进 `DebugMacros.h`：
   - 不同引擎版本对它的包含情况不一样，**有的版本可能默认已经包含了**；
   - 为了安全，显式保留这条 include，这样任何引擎版本下都不会缺。

> 顺带一提：视频里为了教学曾经定义过一个 `#define` 符号（值为 30）的宏——这种"魔法数字宏"容易污染代码，讲师把它**删掉**了。给宏起有意义的名字，不要为写宏而写宏。

---

## 三、使用侧：按需 include，而不是总头文件

在需要调试宏的地方（例如 `Item.cpp`），把原来的

```cpp
#include "Slash.h"        // 总头文件：连带引入一大堆东西
```

替换成更聚焦的：

```cpp
#include "DebugMacros.h"  // 只引入调试形状绘制
```

这样 `Slash.h` 不再是唯一入口，调试能力被收敛到一个**专门的头文件**里——想用调试宏的类只 include 它，职责更清晰、依赖更小。

### 编译注意

头文件结构发生变化时，**热重载（Hot Reload）不一定能正确检测到**。视频里的做法：

1. 完全关闭编辑器；
2. 在 Visual Studio 里按 `Ctrl + Shift + B` **构建整个解决方案**；
3. 重新启动编辑器，播放验证——功能与之前完全一致，说明搬家成功。

---

## 四、小结：模块化头文件的收益

| 做法 | 收益 |
| --- | --- |
| 调试宏独立成 `DebugMacros.h` | 想用调试能力的类按需 include，不连带引入整个项目头文件 |
| 头文件放 `Source/`（而非 Intermediate） | 编译后不会被自动清理删除 |
| 需要的系统头文件（如 `DrawDebugHelpers.h`）在自定义头文件内自包含 | 换引擎版本也安全 |
| 删除无意义的教学宏（`#define 30`） | 避免魔法数字污染代码 |

**经验要点：**
- Intermediate 目录 = 自动生成、每次编译重建，**别把源码放进去**；
- 好的头文件边界 = "谁需要谁 include"，而不是"所有人拿到一切"；
- `DrawDebugHelpers` 还能画更多形状（圆、盒、胶囊……），本集不逐一展开——**目前掌握球/线/点/向量这套调试工具已经够用，等真需要时再去查它**。
