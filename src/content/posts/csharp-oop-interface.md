我是软件工程大二的学生,这学期跟着讲师 TOM 用 Unity 2023.2.20f1c1 加 Visual Studio 2022 上 C# 入门课,前面刚把类、继承用熟,这一节轮到接口。上课时我以为接口不过就是把方法登记个名字;课后把讲义翻了两遍,又亲手写代码验证,才慢慢咂摸出味道:接口解决的是"我不在乎对面是谁,只要它能响应我这套指令"。

## 接口,我这样理解

我把接口理解成一份"能力清单"或"契约":它只规定一个东西必须具备哪些能力,至于每项能力怎么实现,一概不管。比如"会飞""可受伤",我只关心它有没有这些本事,不关心靠翅膀还是引擎、掉 1 点还是 10 点血。讲义的说法是:接口只声明方法或属性、不提供实现,只管说"有什么能力","怎么做"不管;类实现它就像签合同,承诺"这些我确实都会"。

## 怎么定义一个接口并实现

定义接口用 interface 关键字,习惯以大写 I 开头,成员只有签名:方法写返回类型、名字和参数,后面接分号,没有实现体;属性只写声明。我照着讲义写了个"可受伤"的接口:

```csharp
// 能力契约:可受伤
public interface IDamageable
{
    // 只声明受伤方法,不写具体逻辑
    void TakeDamage(int amount);
}
```

实现靠类:类名加冒号接上接口名,再把每个成员补齐实现。讲义里 Dog、Cat 实现 IAnimal 就是这么干的,我在 Unity 里试了个敌人:

```csharp
// 敌人实现接口,给出受伤的具体逻辑
public class Enemy : IDamageable
{
    public void TakeDamage(int amount)
    {
        Debug.Log("敌人受到 " + amount + " 点伤害");
    }
}
```

编译通过那刻我才明白:接口像一张只写要求的空头支票,实现类才是兑现的地方。

## 一个类实现多个接口 与 接口间的差异

最让我开眼界的是能力可以叠加:C# 里一个类只能继承一个父类,却能同时实现好几个接口,名字用逗号隔开。讲义里的 SmartPhone 一次实现 ICall、ITakePhoto、IChargeable,能打电话、能拍照、能充电。继承回答"它是什么",子类天生拥有父类的一切;接口回答"它能做什么",鸟和飞机也能都实现"会飞"。为了验证我写了段代码:

```csharp
// 接口1:会飞
public interface IFlyable
{
    void Fly();
}

// 一个类同时实现两个接口:能飞,也能受伤
public class Drone : IFlyable, IDamageable
{
    public void Fly() { Debug.Log("无人机起飞"); }

    public void TakeDamage(int amount)
    {
        Debug.Log("无人机被击中,损失 " + amount);
    }
}
```

讲义还把接口和抽象类对比过:抽象类能放字段、构造方法,还能带写好的方法,适合共享代码和状态;接口只能放成员签名,适合定义行为规范。

## 容易踩的坑

对着讲义里接口与类的对比表,我给自己记下几处容易翻车的地方:

1. 漏实现成员:类一旦实现接口,每个成员都得给出实现,少一个就编译报错。
2. 修饰符:接口成员默认 public,不让加访问修饰符;而实现类的方法必须写成 public,才能兑现这份公开承诺。
3. 把接口当类 new:接口只是契约,new 不出来;要先用实现类 new 出对象,再用接口变量去装,讲义里 IAnimal animal = new Dog(...) 就是左边接口、右边具体类。
4. 签名不一致:接口声明 void Activate(),实现里返回类型或参数写错,编译器就不认账,照样报"未实现"。
5. 塞字段:接口不能包含字段,能放的只有方法、属性这类声明。

## 小结与我的思考

一句话总结这节:接口约定"会什么",类负责"怎么做"。interface 定义契约,成员只有签名、默认 public、不能含字段,接口本身不能实例化;类用冒号实现并补全成员;一个类能实现多个接口。课上 TOM 带我们用 IShape 让圆形、矩形各自算面积再统一输出,我第一次体会到:大家遵守同一份接口,外面就能用一套代码指挥完全不同的对象。

我的思考是,接口适合当"系统的插座":先约定插孔规格,让各种类自己来适配。随堂作业里 SkillManager 用一个存 `List<ISkill>` 的列表装下火球术和治疗术,遍历时统一 Activate;以后加新技能,新类实现 ISkill 就能直接塞进去。现在我写脚本前会先问自己:在乎"它是什么"还是"它能做什么"?答案是后者,就掏 interface。
