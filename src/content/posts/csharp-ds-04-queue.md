"队列"这节课上完,我又自己把示例代码重新敲了一遍,才敢说真的把它弄明白了。上课前,我以为队列无非是个"能装东西的容器",和数组差不多;课后才慢慢体会到,决定一种数据结构用途的,往往就是"先来后到"这四个字。这篇笔记想聊聊我对队列的理解、几个常用操作、它适合用在哪,以及我踩过或差点踩过的小坑。

## 队列我这样理解

队列(Queue)是先进先出(First In First Out,FIFO)的线性结构。老师用食堂排队打比方:先来的人先打到饭、先离开队伍,后来的只能排在后面,谁都不能插队。放进队列的元素一律排在队尾,能取出来的永远是队头那一个。

我一开始总把它和之前学过的栈弄混。栈是后进先出,像一摞盘子,后放上去的先被拿走;队列恰好反过来,像一支队伍,先到先服务。同样依次放入 1、2、3,栈依次取出是 3、2、1,队列取出则是 1、2、3。想明白这组对比,后面看用法就顺多了。

## 常用操作 Enqueue/Dequeue/Peek/Count

队列的常用操作其实没几个,课上总结下来就是:Enqueue 在队尾插入元素,Dequeue 移除队头并把它返回,Peek 只查看队头不删除,Count 给出当前元素个数,另外还有个 Clear 能一键清空。为了验证,我照着讲义写了个小例子:

```csharp
Queue<int> queue = new Queue<int>();
queue.Enqueue(1); // 从队尾依次加入 1、2
queue.Enqueue(2);
int first = queue.Dequeue(); // 取出队头 1,队列里剩 2
int peek = queue.Peek();     // 只查看队头 2,不删除
Debug.Log(queue.Count);      // 输出 1
Debug.Log(first + " " + peek); // 输出 1 2
```

跑出来的结果和预想一致,不过我也注意到一个细节:Dequeue 之后 Count 跟着变小了,说明它是真的把元素移走;而 Peek 只是"看一眼",队里那个元素还在。

## 队列适合干什么

想清楚先进先出,队列的用武之地就很好判断了:凡是讲究"先来后到、按顺序处理"的场景都合适。比如一批指令或消息要按到达的先后逐个执行,先到的先处理,队列天然就能保证顺序不乱,以后做 Unity 里这类"排队干活"的逻辑,我会优先想到它。

课堂案例走的也是这个思路:把数组 {1,2,3,4,5,6} 里的数字按顺序 Enqueue 进 Queue&lt;int&gt;,再用 foreach 遍历输出,得到的还是 1 到 6——入队顺序就是输出顺序。我原本担心 foreach 会不会从奇怪的方向开始,跑完才确认它是从队首一路走到队尾的。

这节课里我最有印象的还是那道作业:要求只用队列自身的操作,把依次入队的"A""B""C"反转成"C""B""A"输出,不能用别的辅助结构。做法是先把队头 Dequeue 出来暂存,递归处理剩下的元素,最后再把这个元素 Enqueue 回队尾。我盯着递归看了好一会儿才转过弯:它是一层一层把队头挪到队尾,顺序就这样被倒了过来。原来队列加上递归也能玩出这种花样。

## 容易踩的坑

- 操作前先判空。讲义特别提醒:队列为空时 Dequeue 会抛异常,Peek 也没有队头可看,所以我现在习惯先看一眼 Count 再动手。
- 别忘了 Dequeue 有返回值。它删掉队头的同时会把那个元素返回出来,得接住它再用,不然被删的数据就找不回了。
- foreach 按队首到队尾遍历。遍历顺序就是入队顺序;想倒着输出不能指望它,得自己处理,课上那道反转题就是例子。
- Enqueue 是把元素加到队尾。新来的永远排在最后,别把它当成"往队头塞"来用。

## 小结与我的思考

整节课可以压缩成三句话:队列是先进先出的线性结构,核心操作是 Enqueue、Dequeue、Peek、Count(外加 Clear),foreach 会从队首遍历到队尾。它是处理"排队"这类需求最顺手的数据结构。

最后留一个我自己琢磨的疑问:课上反转队列用的是递归,一次 Dequeue、一次递归调用、一次 Enqueue,如果队列里有成千上万个元素,递归会不会把调用栈压得很深、拖慢程序?有没有不递归的写法?这个问题我打算找个时间自己动手验证一下。
